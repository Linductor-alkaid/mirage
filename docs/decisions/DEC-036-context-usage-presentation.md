# DEC-036：上下文占用比例与真实数据来源

> 状态：Accepted
> 日期：2026-10-04
> 负责人：Mirage 维护者
> 工作项：M6-06

## 背景与决策

维护者指定按ZCode的比例圆环展示上下文。沿用DEC-035外观，采用小圆环入口、紧凑
Token摘要和横向进度条；点击展开，保留键盘操作。以pinned Mira ModelResponse.usage
最近一次成功请求的input_tokens为分子，优先使用Exact/ProviderReported；自M6-45起，
缺少有效报告时按 [DEC-102](DEC-102-estimated-context-usage.md) 使用Mira请求输入估算，
明确标注“本地估算”。不把输出Token或多次调用的累计消耗作为上下文占用。工具循环取
最终回复调用的输入用量。

新增可选model.context_window_tokens配置（0/缺失表示未知，非零2048–2000000）。
它是用户配置的上下文窗口预算，同时映射Mira公开ProfileLimits，不宣称供应商自动发现。
无配置时保持既有Mira默认运行预算，但UI分母未知。用量随轮次通过可选context_usage
对象传输，包括input_tokens、window_tokens和model；旧消息缺字段仍可解析，旧JSON保持。
UI显示“上次请求”，草稿与尚未完成的请求不伪装为实时Token计数；失败/取消不产生新占用。
会话持久化保存最近一次成功请求的用量快照及其轮次序列，历史同步独立返回该快照，
不受历史轮数截断影响；切换会话、重连和服务重启后仍可查看。不得从文字重建伪精确值。

2026-10-18（M6-43；缺用量策略后由DEC-102调整）：按维护者要求补齐会话级存储。`context_usage_sequence` 标识
快照所属序列；成功但缺用量也推进序列并清空快照，失败/取消和普通进行中轮次保留
上次成功值。编辑替换末轮时清空被替换的快照，并以新序列阻止旧事件恢复它。
`session.chat.history` 的顶层可选 `context_usage` / `context_usage_sequence` 与
schema 1 会话文件的同名字段承载快照；缺字段的旧会话显示未知，旧协议仍可解析。
该值始终表示“上次请求”，不声称是草稿或执行中的实时占用。不新增并发路径或修改依赖。

## 替代方案与影响

拒绝将字节比例冒充精确计数及硬编码供应商窗口。无供应商报告时可显示明确标注的本地估算；
既无有效报告也无实际请求估算时显示未知。未配置窗口时分母及比例始终未知。
不新增异步任务、不变更Executor所有权，不修改pinned依赖；数据沿现有结算/事件/历史路径。

## 验收

检查已知/未知/溢出、最新轮次与迟到事件、模型预算校验、可选IPC兼容及真实模型请求。
Linux正常/最小窗口、明暗主题截图；Windows待维护者在目标环境补跑。
