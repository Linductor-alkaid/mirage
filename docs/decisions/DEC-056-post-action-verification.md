## 选型与边界

Mira AgentLoop 已提供设备 Observe/Act/Verify 和 ILoopVerifier；ConversationLoop 明确
只以 Answered 结束，不执行设备验证。原生会话继续复用后者及公开 supplier，不另建

## 契约

本节保留首交付的历史范围；默认门控与终态要求已由文末分层修订替代。

四个会话修改工具升至 2.1.0，原有 required 字段保持。新增可选 verify_kind：
window_focused、window_title_equals、semantic_node_exists；后两者分别需 expected_title
或 expected_role/expected_name。字符串各最多 1024 UTF-8 字节。预期条件必须在修改
前声明，验证工具不能事后更换；激活省略条件时默认核验目标前台窗口，其他动作省略
条件仍可派发，但终态不能报告业务验证成功。匹配只证明声明的局部后条件，不能证明
任意用户意图或因果关系。

每次 handler 结束、输入租约结算后强制新观察。前台窗口、任务/会话/epoch、取消与
采集前后几何须一致；语义条件使用新树、512 节点预算，名字/角色精确匹配，重复命中
拒绝。单次核验协作预算 1 秒，无固定 sleep 作为证据。回执区分派发与验证，并携带
action_id、verification.status/reason/condition_digest/evidence_id/environment_epoch，
以及实际窗口/几何/语义匹配数的 observed_digest 和 captured_at_ms。标题最多 64 KiB；
新鲜度用单调时钟，时间戳仅供展示。
原始期望文本与语义名不复制到普通过程面，只保留摘要和身份。

新增只读 desktop.action.verify(action_id)，仅核验本轮最近动作、固定条件及当前 epoch。
允许异步业务更新后再次采集，不重新派发动作，不改变条件。未验证最近动作时拒绝
下一修改；不确定副作用后本轮所有修改保持拒绝，等待用户检查。失败/旧/异会话 ID
不能恢复为成功。最多 32 条动作记录，沿用 loop 的总工具预算，无队列/worker/定时器。

supplier 仅送非可信动作证据摘要；终态再采集核验最近动作。只有所有声明的动作
后条件都有通过证据，宿主才保留模型回答，并明确其核验范围。规范失败 ToolResultPart
是失败事实源，过程投影的 16 KiB/总 64 KiB 预算不能绕过门禁。拒绝、缺条件、条件
不符、观察失败、环境变化或 uncertain 时转为安全 failed/未验证终态，抑制模型的
“已成功”回答；Cancelled 优先。过程卡显示目标和核验状态，展开可查证据身份。

后的建议：普通键鼠动作不再默认要求逐动作业务后条件通过才允许继续；按有界动作组、

### 默认执行与观察策略

普通移动、点击/多击、拖动、滚动、按键/组合键与文本输入只需表达动作意图，默认不要求
模型提供 `verify_kind` 或业务期望值。执行层完成本次序列、结算自身输入释放及异常后，
即可返回实际执行结果；不为每个动作默认追加 OCR、语义匹配或独立模型验证。DEC-110
的自然时序由本地完成，“执行完再返回或验证”只约束顺序。

模型正常下一轮需要的截图/结构状态同时承担反馈，不额外启动相同问题的验证调用。
是否取得新帧不决定输入调用是否已完成；后续操作仍须有满足当前身份、权限、变换、
焦点及新鲜度要求的依据。不能把可选观察理解为旧引用永久有效。

上下文稳定且不需中途分支的输入，可组成有界动作组，例如“聚焦搜索框→输入→Enter”，
在组末统一观察。组内复用现有输入 owner，逐步检查取消与平台屏障，首个失败即停止
后续步骤并结算；回执报告实际完成前缀和未执行部分。组能力、步数/总时间预算、目标
与依赖范围须在 M7-25 冻结后接线，不由本决策直接开放任意脚本、未知焦点跨越或新调度器。

当下一步依赖菜单出现、新窗口、可编辑目标或异步结果时，在该依赖处取得观察；已有
可靠平台条件时可用有界本地等待/验证。权限、目标身份、遮挡、焦点/源变化、人类接管
等派发守卫继续有效，不因省略业务验证而移除。固定 sleep 不构成成功证据。

### 显式条件与恢复范围

业务条件是可选且有明确作用域的约束：用于依赖步骤、动作组或任务目标，在相应操作
前固定目标、预期、证据方法及哪些后续步骤依赖它。已有的文本/窗口/语义条件语义保持；
条件未匹配或取证不可用时，仅阻止依赖该条件的后续修改或成功声明，不默认封锁所有
无关修改。只读重观察、规划和不依赖该条件且通过输入守卫的恢复动作仍可进行。

恢复动作不能暗中消除原条件：修正目标状态后可对同一条件重新取证，未经明确改变任务
目标不能把原任务未满足写成成功。固定精确值条件也不能因 OCR、新帧或模型认为正确
而降格通过。`desktop.action.verify` 保持只读、固定条件重验，不重新派发输入或复制
按键；具体条件引用、依赖表达及旧客户端兼容由 M7-25 与 M7-32 冻结。

| 当前事实 | 默认处置 |
| --- | --- |
| 执行完成、输入已释放，未请求业务条件 | 可继续合规操作；业务效果未知单独表达，不产生 unverified 全局围栏 |
| 已请求条件未匹配或取证不可用，执行结果确定 | 保留条件事实，阻止其依赖步骤；允许观察、重规划和合规恢复 |
| 前置干净拒绝、已确认无副作用 | 返回拒绝，允许修正后再试，不算动作成功 |
| 已知执行失败或部分执行，已释放且副作用边界明确 | 返回失败及完成前缀，停止原动作组；取得必要观察后重新规划，不自动重发整组 |
| 执行副作用未知、释放失败或状态无法确认 | 保留现行围栏；依既有明确恢复规则处理，不能当作“业务尚未验证”放行 |
| 撤权、接管、设备掉线、取消或 shutdown | 阻止受影响的新输入，按既有 owner 清理/结算；取消优先 |

原生 API 返回、异常、事件计数、部分派发、超时和释放状态继续是执行事实源。不能从
OCR 未匹配推导派发失败，也不能从截图成功消除执行 uncertain；DEC-086 已有的特定
机器证据恢复例外保留。可恢复的只读错误在后续有效观察补齐后不永久毒化任务。

### 回执与任务终态

新回执须分别表达执行结果、观察可用性和已选业务条件结果，携带 action/group identity、
完成前缀、输入释放及不确定性、证据来源/时刻/目标和条件依赖。未请求条件不等于匹配，
观察可用不等于业务成功；不得为解除门禁把 `verified` 强制置 true。上述为已接受的
语义要求，已实现子集的字段及版本见下节；动作组前缀/精确值等剩余契约继续由 M7-25/32 冻结。

任务结束按用户目标检查结果，可复用仍新鲜、身份一致且发生于相关动作之后的观察。
普通 GUI 任务允许模型基于这些观察判断进展并作答，宿主如实区分模型判断、局部机器
条件证明与执行事实；不再要求所有历史键鼠记录均 machine-verified 才保留回答，也不
无条件再次采集最近动作。依赖目标已改变、证据过期或不足时才补必要观察。

显式必需的业务条件尚未满足、终态结果证据不足或仍有执行/释放围栏时不能声明完成；
可以返回部分完成、失败或不确定及原因。新终态规则不授权仅凭“工具没报错”声明成功。

### v2 首增量契约与范围

会话修改工具（窗口/键鼠、视觉编号/区域、共享输入及应用启动）的 v2 首交付版本为 `3.0.0`。
后续 DEC-110 自动接近点击将三条物理 click 工具升至 `4.0.0`（条件/回执仍为本策略 v2）；
只读 `desktop.action.verify` 为 `2.0.0`。旧版本 proposal 按 Mira registry 的版本匹配
规则拒绝，不在活动回合或持久历史中热改语义；workflow 显式固定条件路径继续保持取证。
应用工具仍默认核验 `application_running`，窗口激活默认核验 `window_focused`；普通
键鼠不默认创建条件，区域/共享 schema 的 verify_kind 改为可选。

回执保留外层输入 schema=2 和 dispatched/input_released 等事实；`verification` 增加
`policy_version=2`、`execution_status`（completed/rejected/uncertain）、`input_released`、
`condition_requested`、`observation_status`（available/unavailable）、`depends_on`、
`effect_uncertain`。未选业务条件时 `status=not_requested`、`verified=false`、
`evidence_scope=execution_only`，不截图/OCR；进程/窗口/文本条件保持各自局部意义。
副作用可能发生与执行不确定分别表达，桌面过程卡对 execution_only 显示“已执行”。

可选 `depends_on` 是最多 8 个不重复的本轮保留 action_id。只接受已请求且已匹配的
固定条件，并核验相同 authority、当前动作 epoch 和 5 秒本地证据有效期。供给
本次模型请求时仍新鲜的条件 ID，可由该请求的下一次修改尝试消费，推理耗时本身
不使其失效；不在派发入口重新采集，以免退役模型所依据的图像引用。目标/焦点/
像素的实际派发前检查仍由原 Provider 执行，此绑定不保证推理期间桌面未变化。
未消费的过期证明、未匹配或 epoch/authority 已变的证明拒绝，不自动续期；模型
可显式只读重验。不声明依赖的恢复动作仍过原输入守卫，原未满足条件继续阻止成功终态。
只读重验可定位保留的较早记录；独立恢复后的普通动作 epoch 可更新，authority 改变
则拒绝，不能靠重验绕过接管或释放失败。记录窗口仍为 32 活动/128 归档，未满足条件
和未知副作用不归档；过旧 ID 明确拒绝。

`settle()` 不采集；使用当前 authority/epoch 下最近 5 秒内的成功桌面观察检查点或
局部条件证据；证据若在供给本次模型请求时满足新鲜度，模型本次推理耗时本身不
使已观察结果失效。该接纳仅属于本次请求，仍受 owner deadline/取消及当前
epoch/authority 检查，新输入立即清除，不按每轮自动续期。检查点仅来自 capture、窗口前台/列表、语义树、OCR/mark，
不接受剪贴板、进程查询或其他普通只读工具冒充桌面观察；源帧新鲜度仍由各采集路径
核验。仍未满足的显式条件及执行围栏阻止成功，取消优先；失败的只读 verify 不被
误判为未知键鼠副作用。规范失败的真实 mutation 仍以宿主记录对账，未知回执保持封锁。

机器可读子集为 `tests/integration/data/desktop_action_policy_v2.json`，由
`desktop_action_policy_test` 对账并覆盖默认无条件、依赖/恢复、跨 epoch/authority、
归档和不确定性。新增任意跨工具动作组、已知部分执行前缀、精确文本值及默认自然
时序不包含在此首增量；这些结果不得由现有测试通过替代，工作项继续推进。

ApplicationProvider 路径不依赖旧点击；历史失败保留，不改为成功。取消、
接管、撤权和无法确认释放仍按具体状态阻止受影响路径。此前验证记录保留历史含义，
