# DEC-117：Runtime 常驻感知与自主动作执行

> 状态：Accepted（维护者 2026-10-27 明确授权）
> 日期：2026-10-27
> 负责人：Mirage 维护者
> 工作项：M9-22；关联 M9-06/07/09/10/11/19/21
> 调查：[最新会话与外部项目对照](../research/2026-10-27-event-driven-observation-and-action-gates.md)

## 背景与问题

最近会话的鼠标已完成移动，但到达截图门禁以局部外观变化拒绝按下，并将移动
副作用归入点击不确定；text_only OCR 还清除了此前已见图像的输入意图。既有连续
采集/处理链路随任务退出，无法在任务之间保留运行中的当前状态和事件。

## 决策

1. 复用现有连续采集、Mirador 分析、当前对象状态和有界事件日志，由 Runtime Service
   持有常驻 owner。初始化已有授权时静默启动；首次交互授权建立后也可接管该会话。
   正常任务结束/取消仅释放自己的访问租约，不销毁进程级感知。没有授权时保持未启动，
   后台不得弹授权窗口。授权失效/撤回、接管及服务关闭停止对应生产和访问。
2. 每个任务仍独立授权、取消及持有输入引用/语义标定；平台流和当前状态可复用，
   不跨任务继承输入权限、待核验动作或模型绑定。新任务默认只见当前对象和接入后的
   事件。共享日志有界保留，单个消费者确认不能清除其他消费者尚需的记录。
3. 普通自主 click/scroll/drag/key/text 不使用像素相似度、裁剪 kGlobal/unknown、
   外观不可证明稳定作为派发否决。移除默认前置像素取帧和到达后截图门禁；保持自然
   时序、确定的目标坐标映射、权限、取消/接管、参数/几何边界及输入释放契约。
   只读采集失败不冒充输入执行不确定。确实已派发而结果未知时保留真实 uncertainty。
4. 回执区分 approach_completed、press_dispatched、release_confirmed 与观察到的效果。
   鼠标移动成功不能推断按钮可能已按下。显式后条件仍按固定条件取新证据；普通动作
   不默认要求后置帧。用户业务成功与输入成功保持分别表达。
5. 前台优先消费常驻最新帧和事件/当前对象状态，图像只按需裁剪、编码和供给。
   text_only OCR 不仅因为“不供图”而退休仍有效的执行上下文。背景继续运行现有
   图像采集/轻量变化检测；Mirador 不靠事件凭空生成观察。没有新相关事件时不诱导
   模型 wait+capture 轮询，不每轮重复送同图。源 buffer、copy、识别、编码与供图分别计数。
6. 沿用唯一 Executor owner、blocking worker、timer、mailbox 和背压。资源串行访问，
   前台输入暂停背景采样/分析；关闭先停常驻采集，再排空任务和分析，最后 shutdown。
   不修改 pinned 依赖，不新建并发设施。

以下旧条款自本决定接受日起失效，不再作为新实现/评审/验收依据；保留原文仅作历史证据：

| --- | --- | --- |
| DEC-072/077/081 | 普通动作前必须以新帧证明目标像素未变；共享流只能归单任务 | 系统授权、坐标空间、权限、任务引用、动作后新证据的真实性 |
| DEC-074/115 | 任务结束销毁唯一连续采集/感知 owner；不能跨任务复用底层授权流 | 有界历史/预览、epoch、取消、来源和消费者隔离 |

| DEC-107 | 输入必须重新取帧核验；仅按单任务短龄缓存复用 | 采集呈现租约尽早释放、真实时间水位、不把新帧当业务成功 |
| DEC-110 | 自动移动之后必须截图重验才按下 | 本地自然时序、完整按下/释放、受控预算和设备兼容性 |
| DEC-091 | text_only 无图必须清除输入上下文的推导 | 文本优先、平台与模型语义分离、明确证据新鲜度 |
| DEC-058/063/064/065/066/100 | 普通编号/ROI/滚动/拖动的像素相等重验、到达截图及颜色变化必须拒绝的历史验收 | 引用身份、坐标变换、几何、容量、平台资源所有权及产品配置 |
| DEC-109 | 将长期观察消费者限定为单任务、按目标相似度否决普通动作的推导 | 轻量增量、对象/事件、按需 VLM、资源预算；Runtime 自身是常驻消费者 |

实现范围及实际测试见 M9-22 验证记录；未验证平台不宣称完成。

## 备选方案

保留像素硬门禁并调整阈值仍会把正常悬停、动画和配色变化作为身份判断；不采用。
只改模型提示、继续每次工具调用重新采集，也无法改变短生命周期与重复取帧成本。
平台 damage 可进一步减少源工作，但当前不作为常驻 owner 和事件消费的前置条件。

## 影响与风险

常驻源在无任务时仍占用有界采集和 OCR 资源，需要单独进行长期资源验收。
取消外观否决后，桌面可能在规划与按下之间改变；继续明确输入实际派发阶段，
在依赖或任务边界验证效果，不将任何一次输入回执宣称为业务成功。
通知只用于唤醒，日志容量/TTL 与 gap 才是消费者判断历史是否完整的事实。
