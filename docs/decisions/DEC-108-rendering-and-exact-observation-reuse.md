# DEC-108：按可见内容呈现与精确图像结果复用

> 状态：Accepted
> 日期：2026-10-19
> 负责人：Mirage 维护者
> 工作项：M6-47 / M7-24 / M8-13
> 细化：DEC-084 / DEC-101 / DEC-107

## 背景与决策

维护者要求优化前端、后端及 pet 的 CPU、内存和响应速度。历史消息每次构建完整控件树，
pet 的 512×512 RGBA 全帧缓存和持续 ImageStream 刷新产生与当前可见变化不相称的开销。

1. 消息行保留原始高度与滚动坐标，只为视口及预留区构建正文和控件；正在选择的消息
   保持实体。滚动改变必须请求重新组合，不能只移动旧内容而出现空白。
2. pet 保留原始分辨率和播放时钟。每帧仅存非零 RGBA 的包围矩形，呈现时还原原始
   画布；不裁掉任何非零像素，不改素材和摘要。仅保留一个 clip 与当前/中性帧。
3. pet 使用 EUI 公共 GPU 图像导入接口，在 UI 线程上传变化帧，复用一个纹理，避免
   ImageStream 绑定造成静态/重复帧持续重绘。动画唤醒沿既有 Executor timer 管理，
   普通播放按源帧时长唤醒；气泡滚动保留原有刷新节奏。隐藏停止动画，恢复重发当前帧。
4. 成功 OCR 可在同一 DesktopImageTurn 内复用精确 PNG 摘要、epoch 一致的最近结果。
   先走现有采集/授权/取消检查；返回元数据仍来自当前观察，不延长图像寿命或省略动作
   守卫。模型和 OCR pipeline 在轮次内固定，结果不跨轮次、pipeline 或授权传播。

## 备选与边界

不采用降低素材分辨率或帧率，避免损失 DPI 和动作细节。不用感知指纹判断 OCR 精确
一致性。UI GPU 适配限于现行 OpenGL 产品构建；未来更换后端必须实现对应上传路径，
不把原生资源类型暴露到 Mirage 公共 API。纹理由 EUI 的 lifetime 引用保活，必须在
窗口设备销毁前释放；失败须可见，不静默退回持续刷新。

## 验证方式

同机配对输入测试、像素还原比较、私有 X11 pet 呈现与生命周期、OCR 调用次数及
取消/授权/epoch 回归、sanitizer。性能数据与平台限制见
[维护计划](../plans/maintenance-performance-20261019.md)。

## 2026-10-23：长会话几何复用细化（M6-48）

离屏正文裁剪仍每帧进入 Markdown 高度估算（包括段落遍历与上游布局缓存查找），且原精确 contentKey 超过 64 KiB 后
退回两次全量测量。现在在 UI owner 内保存当前会话逐消息的精确源快照与两个宽度的
几何（含滚动条 gutter），仅重新测量发生变化的消息；正文、状态、失败原因、过程
parts、展开状态与 timings 逐项比较，不以 hash 或事件序号代替内容。消息顺序、
视口、字体/缩放和主题变化推动有界 revision，作为 EUI 公共 contentKey。composer
增高和主题切换只改变 scroll key；字体/缩放使全部几何失效，宽度按实际值分别测量。

保留最多 80 条消息、额外源快照预算 8 MiB，只持有一个会话；超预算清空缓存并退回
原测量，不截断正文。复用 EUI 公开 Markdown/字体/ScrollView 实现，不新增排版器、
线程、事件队列或异步路径。验收与平台限制见
[2026-10-23 性能记录](../benchmarks/native-long-session-20261023.md)。


## 2026-10-23：授权消费 EUI 视口能力（M6-50）

维护者在本轮明确授权独立 EUI 分支开发和修复 PR，见 EUI-20261023-001。
Mirage 消费公共 MarkdownBuilder viewport，由 EUI 承担通用块/行布局复用与
控件构建预算；Mirage 只计算产品的局部视口并保留既有消息几何和滚动状态。
默认完整 builder 用于按下时的全正文选区快照，避免裁掉的行改变 UTF-8 引用。
不复制依赖私有类型，不引入 worker/定时器，也不把产品消息或选区策略下沉 EUI。
上游 [PR #117](https://github.com/sudoevolve/EUI-NEO/pull/117)，集成 pin/
四后端验证/平台限制见[审计](../supply-chain/eui-dev-20261023.md)。


## 2026-10-23：已知历史的溢出下界（M6-51）

消费 pinned EUI ScrollView 的两阶段测量：完整宽度的首轮只作溢出判定，
带 gutter 宽度的末轮给出真实范围。精确源缓存中未变化行的高度与行间距
提供非负总高的下界，留出一个逻辑单位边界余量后，只在能证明溢出时省去
首轮变化长文布局。该代理仅存在于无 ScrollView root 的完整宽度测量 UI，
真实内容和末轮精确几何不变；不能证明或任何失效均完整测量。
不修改依赖、不增加异步路径；依赖升级必须重验首轮高度的使用方式。
设计及取证见[溢出探测记录](../benchmarks/native-overflow-probe-20261023.md)。
