# DEC-099：完整点击序列

## 契约

可见目标的 `desktop.session.click`、`desktop.vision.click` 和
`desktop.vision.click_region` 增加可选整数 `click_count`，接受 1–32，默认 1。
次数表示同一位置的一次完整点击序列：一次权限判定、目标重验和单写者 lease 内连续
发送指定数量的按下/释放；2 为双击，3 为三击，之后统一观察与核验；各次之间没有模型调用、截图或权限 UI。
不能用两次独立工具调用模拟双击。语义 `desktop.input.click` 仍表示一次语义激活，
不以重复 Invoke 伪装鼠标双击；需要物理双击时选择上述可见目标工具。

InputProvider 增加完整点击序列入口，旧单击调用保持不变；未实现的后端只允许
序列长度 1 转发旧单击，多次显式返回不可用，不降级为单击。共享输入 action 增加
默认 1 的次数字段。Linux X11 和 Portal 后端在原 Executor 有界调用中直接发送
序列，不增加线程、调度器或独立重试。非法参数在授权和输入前拒绝。
新增虚函数改变 C++ ABI，消费者须配套重编译；IPC 和会话持久化格式不变。

取消、超时、失败或撤权阻止后续按下，但不能阻止已拥有按钮的释放。
第一次点击后失败按不确定副作用报告，禁止自动重试整个序列；释放失败继续封锁输入。
序列完成只证明输入已发送，业务结果仍依赖动作后条件和新观察。

单次最多 32 次是连续输入容量保护，不是把接口分成单击/双击特例；
`click_sequence_at(..., count)` 为唯一通用入口，三个工具和两个后端复用同一上限。
取消、动作期限和释放失败均可提前终止序列，不自动补齐尚未发送的点击。
需要在观察变化后继续的动作应拆成不同意图，不把无限点击塞入一个 lease。

## 验证与平台边界

覆盖默认单击、双击/三击/多次和上限事件顺序、非法次数、取消/超时、序列中及末次按下/释放失败及目标/权限
守卫。用私有 Xvfb 的实际 XTest 事件和 GTK 双击/三击识别验证 Linux；Portal 事件序列
通过可注入边界验证，真实 compositor / Windows 在对应环境补验，不据 fake 声称通过。
