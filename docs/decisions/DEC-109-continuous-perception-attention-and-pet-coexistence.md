# DEC-109：连续感知、任务注意策略与桌宠共存

> 状态：Proposed（方向来自维护者 2026-10-19/20 需求；具体契约及默认策略待冻结）
> 日期：2026-10-19
> 更新日期：2026-10-22（新增上游关系/规划的局部消费；产品策略和平台契约仍待冻结）
> 负责人：Mirage 维护者；通用视觉能力由 Mirador 上游维护者负责
> 冻结里程碑：M9-05/06/07/08/09/13/17/18/19；桌宠平台能力与 M8-06 协同
> 替代/被替代：无；拟细化 DEC-091、DEC-103/105/106/107/108

## 背景与问题

任务执行期间需要持续掌握整屏变化，同时保持 pet 动画可见，减少重复截图、OCR、
模型图像输入和无关变化引起的动作拒绝。现有 M9 首增量只有无像素 VisualScene
状态与语义绑定；DEC-107 已把隐藏缩短至采集区间，DEC-108 提供精确 OCR 结果复用，
这些都不等于连续感知、跨帧语义接线或无闪烁采集已经交付。

[Mirador #41](https://github.com/Linductor-alkaid/mirador/issues/41) 的直接问题是密集
文字的 rec 成本与超时丢弃；其
[2026-10-19 补充](https://github.com/Linductor-alkaid/mirador/issues/41#issuecomment-6258623068)
提出实体整合、连续状态、任务注意策略和选择性通知。以下按这两个交付层次推进，
不让连续感知阻塞直接 OCR 性能修复，也不把建议接口写成 pinned 能力。

## 拟议决策

### 0. 低资源分层方向：轻量增量状态、事件驱动理解、按需 VLM

2026-10-20 维护者补充确认：面向低端设备，采用**轻量级增量视觉状态 + 事件驱动
语义理解 + 按需视觉语言模型（VLM）推理**。核心目标是以尽可能低的计算成本持续
维护环境状态，只在必要时理解变化的语义及其对当前任务的影响。大型 Video-LLM
不作为持续感知的常驻前置；本节方向已确认，DEC-109 的具体协议、阈值、平台能力
和产品默认值仍为 Proposed，未声明完整链路已经交付。

采用**高频轻量观测、变化触发结构更新、低频按需语义推理**：这里的高/低频是
各层相对节奏，不是固定 FPS 或硬实时承诺。无需求暂停、静态退避；无意义动画
及冗余目标不触发重复识别、全量状态复制或模型理解。关键文字的新鲜度、外围巡检
和权限/焦点/接管屏障仍按后文保留，不以省资源跳过必要检查。

| 层与责任方 | 处理与输出 | 边界 |
| --- | --- | --- |
| Mirage Platform / Runtime | 授权采集、源时序/变换、kairo 异步调度、输入执行及动作与视觉反馈关联 | 平台差异在 Backend；不实现第二套视觉跟踪/推理调度器 |
| Mirador 视觉基础设施 | 低成本变化检查，OCR/YOLO/tracker 证据融合、跨帧实体关联、几何空间关系与状态差分，形成带稳定身份和时间的结构状态 | 复用已有原语；连续事件/关系维护的完整通用契约经上游反馈交付，不声称当前 pin 全部支持 |
| Mira 任务控制面，经 Mirage Adapter 接入 | 提供关注区域、任务重要性和观察策略，结合事件及当前任务决定是否升级理解 | 任务意义不由 Mirador 猜测；建议协议待 M9-18 冻结，不假设 pinned Mira 已有完整注意 API |
| 可选 VLM 后端 | 对局部 ROI 或有界关键时间窗口做高级语义解释，再按第 3 节绑定到本地对象 | 不逐帧调用；模型结论保留推断来源，不升级为平台事实、输入权限或成功证据 |

当前状态快照与有界历史事件日志共同提供时间上下文；稳定 ID 仅在来源/会话及
实例代际内有效，不构成永久对象身份。结构差分、几何关系与 VLM 解释分别保存
来源和版本，不能将框的包含关系直接解释成控件业务关系。

UI-Hawk 的历史屏幕理解、ShowUI 的 UI 结构引导视觉压缩、GUI-Eyes 的主动观察，
以及 MiniCPM-o 4.5 的视觉 token 压缩与时分复用（TDM）可作为机制参考。采用这些
思路是 Mirage 的工程取舍，不是论文已证明本架构低资源收益。研究事实、适用限制与原始来源见
[研究映射](../research/2026-10-20-event-driven-incremental-visual-perception.md)。
本次对 MiniCPM 的引用仅限机制借鉴，不引入模型、权重或完整运行时，也不将其
列为本地语义后端候选。参考 Resampler 在高成本推理前压缩视觉表示的思路，以及
Omni-Flow 沿共同时间轴分组输入/输出、显式分界并有界交错推进的方式；具体
映射见第 8 节。按需 VLM 继续使用 Mira 既有模型能力，不绑定 MiniCPM。

#### Mirage 的端侧低负载取舍

本方案首先是桌面产品的资源策略。基础感知不新增常驻视觉编码器、Resampler、
本地 VLM 或专用推理 GPU 要求；继续消费产品已配置的 PP-OCR/可选 YOLO 和
Mirador 原语。已有模型加载、工作区和内部并行也要计入基线，不能只统计新增
对象表或用“推理按需”推导“空闲内存为零”。现有 UI/pet 的呈现 GPU 与推理需求
分别计量，不因此改写已接受的呈现路径。

| 工作状态 | 本地感知工作 | Mira / VLM 参与 |
| --- | --- | --- |
| 无授权观察消费者 | 停止本方案的采集与识别生产，清理临时帧/窗口；Runtime/pet 按各自既有生命周期运行 | 不为感知启动模型请求 |
| 有任务、桌面静态或等待 | 低清/平台 damage 轻量检查，静态退避；按关键证据年龄及外围巡检补必要观察 | 复用当前状态；无任务相关事件不发请求 |
| 局部变化或目标移动 | 更新受影响 ROI/对象；确认身份后继承绑定，目标局部跟踪按需启用 | 已知条件由本地闭环处理，语义不足才升级 |
| 布局突变、歧义或任务确需图像 | 有预算地重建/提取清晰 ROI，局部不足才提供概览或关键帧 | 使用既有任务模型一次有界理解，校验结果版本 |

OCR、YOLO、几何分析与 tracker 是可选择的阶段，不是每帧必跑的组合。先用
现有文字/平台事实完成任务；只对尚缺证据的区域升级检测/跟踪。状态层只维护
有界对象及必要局部关系，不为“空间理解”每帧构建全量两两关系图或复制完整快照。
准确性需要的刷新和动作守卫仍有独立预算，过载时减少背景工作而非静默削弱证据。

MiniCPM 的压缩思想在当前产品中优先落实为**不重复送模、不送无关区域、文本/
差分优先、图片按需**；不为节省模型 token 先增加端侧神经编码和额外推理。
TDM 思想落实为已有事件/观察在消费时按时间归组，复用现有基线与水位字段；
时间单元是供给组织方式，不是新增常驻循环、周期快照、空单元心跳或每秒唤醒
模型。后台感知与模型请求可独立推进，模型只在任务需要时消费最新有效变化。

第一交付优先接通已有变化结果对昂贵阶段的真实门控，并减少重复采集/拷贝/编码，
再做实体身份和事件质量。入口、现有缺口与代码依据见研究记录；全链路验收按
[低负载资源门禁](../design/m9-resource-and-progress-policy.md)执行。低端设备上
先验证不依赖推理 GPU 的感知路径，具体预算在实测前登记；不能以 token 减少
掩盖 CPU、峰值 RSS、唤醒次数或用户应用交互变差。

### 1. 采集与 pet 呈现解耦，按平台选择共存路径

“先截图，再绘制 pet”只能约束应用提交顺序，无法排除合成器中上一帧 pet。
普通屏幕采集读取的是已有合成结果；停止 pet 当前帧绘制也不会恢复其底层像素。
只有平台明确提供独立的排除合成路径，才能同时保持屏幕 pet 可见与采集流无 pet。
不以 sleep、跨进程帧序或暂停动画模拟这种保证。

| 路径 | 适用与限制 | M9 取舍 |
| --- | --- | --- |
| 平台采集排除 pet | Windows 10 2004+ 的 `WDA_EXCLUDEFROMCAPTURE` 是候选；要求 pet 进程设置自有顶层窗口、DWM 合成，逐项验证实际 capture backend | 优先验证；API 成功与查询值不足以证明像素正确；截图排除不等于输入穿透 |
| pet 可见、按需移动 | 缺少独立排除能力的平台；普通背景帧允许带 pet，目标附近冲突时迁移 | 建议 Linux 首个产品增量；移动协议、平台支持和真实 compositor 验收后才启用 |
| 短时隐藏取新帧 | 无安全停靠区、必须获取完整无遮挡图像，且 backend 已支持隐藏与源帧 fence | 保留 DEC-107 有界回退；不按每个背景帧反复隐藏 |
| 无法排除或移动 | 未支持 compositor、撤权或目标仍遮挡 | 观察继续并报告遮挡/能力；相交动作不派发，不伪造完整视野 |

Windows 排除只在 pet 自有进程的 Platform Adapter 内设置，不由 Runtime 越进程设置 HWND。
DXGI/WGC/BitBlt 与透明气泡、阴影、跨屏、窗口重建和输入命中分别验证。黑块/空洞
不是合格的底层画面，不能仅据 affinity 成功宣布支持。
标准 Portal ScreenCast 未提供“排除指定应用窗口”的选项；GNOME 专用能力须单列。
X11 Composite 提供窗口离屏像素，但自行重建桌面还涉及层级、透明、阴影和变换，
不作为本阶段默认路径。Wayland 顶层窗口不假定支持任意绝对定位。

移动避让复用 Runtime 受管 pet 身份、进程启动门禁与 Platform 边界。保护区包含
当前目标及上下文、输入接收窗口/输入框、拖动路径和已声明后条件区域。平台返回
实际几何与版本，包含角色、气泡、尾部及阴影；不采用模型自报窗口身份。
增加安全边距、最短停靠时间及迟滞，防止微小 ROI 更新引起来回移动；具体数值在
M9-17 实测前冻结。用户拖动/接管优先，撤权、取消、超时及关闭均有显式结果。

避让状态按 `visible -> relocation_requested -> moving -> awaiting_fresh_frame -> parked`
推进；失败进入 `occluded/unavailable`。移动及走动动画不阻塞背景观察；相交目标的
输入必须等实际窗口离开保护区、动画路径不再覆盖目标，并取得移动后新帧复核。
动画不是移动完成凭证，也不能让已取消的输入在动画结束后恢复执行。

带 pet 的帧保留真实像素，同时由可信 pet 几何产生遮挡元数据。遮挡仅表示该区域
未知，不是“底层没变化”，也不能把旧画面补成当前事实。移动轨迹、原位置与新位置
的覆盖区域均需失效/重验；过期或缺失几何时采用保守范围。几何遮罩仅能减少无益
识别/通知，不能抹去底层变化或宣布该区域干净。pet 总会占据一块区域；移动方案
兑现的是持续外围感知与目标按需无遮挡，不承诺每帧整屏都无遮挡。

### 2. 连续更新本地状态，按需向模型发布

2026-10-22 实施边界：Mirador master `2a9f483` 已交付 Experimental 的关系、
覆盖绑定/采纳和时间状态/事件，Mirage 在独立 oriented 背景宿主的现有 worker
消费，契约见[连续视觉消费](../design/continuous-visual-analysis.md)。暂定以显式
全帧刷新、完整成功的能力结果开启 token 采纳，其余结果不升级为覆盖证明；
M9-18 继续 In Progress。规划仍在同帧识别/融合后执行，前置选择、无帧焦点查询、
任务策略/日志/gap 恢复与模型供给待冻结；不改变通知或后台运行的产品默认值。

采集、轻量变化检查、昂贵识别和模型唤起分别调度：

1. Platform 提供受权帧、源时序、变换及可用的 damage 信息；无需求时停止。
2. Mirador 变化检查维持整屏外围感知，优先验证任务目标与关键区域。焦点外仍检测
   新窗口、弹窗和显著布局变化；低成本检查不等于已识别外围文字或理解任意画面。
3. 仅对变化且需要识别的 ROI 做 OCR/YOLO，未变对象复用证据；重要文字采用更强
   局部检查与最大证据年龄，不能只凭 dHash。场景切换/覆盖不完整时有界重建。
4. 分开保存最新观测、已确认对象状态和已发布基线；对噪声做有界稳定化，紧急屏障
   不等 debounce。无关变化可更新内部状态，不必通知模型；未分析区域标 pending。
5. 当前模型请求经已有 input supplier 取得有界文本快照/增量；焦点切换可查询已有
   状态，无需等下次像素变化。条件满足/相关变化才触发必要推进，不逐帧调用模型。

“连续”限定为受预算约束的持续采样与状态更新，不保证看到每个显示刷新或短于采样
间隔的瞬态；跳帧可能丢失出现后又消失的内容。可用窗口/焦点平台事件协同本地
屏障，动作仍现场重验，不把“未检测到”推断为全程没有遮挡或变化。

像素变化、语义状态变化与发布事件是三件事。动作/等待完成事件须独立结算，
不能被背景 latest-wins 覆盖。模型推理期间发生普通变化先合并到下一次供给；
危险遮挡/焦点变化由本地输入守卫立即处理，不要求先打断模型请求才能阻止输入。

### 3. 模型赋予语义，Mirage 持有绑定，Mirador 复用视觉状态

延续 DEC-091 第 7 节：模型在正常任务轮次看到候选图像/ROI 后，按临时对象引用
返回 label、角色假设、任务用途或对象关系，以及其依赖证据。标定不要求覆盖所有
候选，按需补齐歧义对象，避免先把几百个框全部送入模型。

Mirage 校验 request/image 基线、source/session、场景、对象 incarnation 与内容版本，
保存带 `llm_annotation` 来源的绑定。后续“搜索框”“保存按钮”的选择先查询本地
有效绑定，再解析当前对象位置；身份/内容不足时回退局部图像。坐标移动与内容
变化分开，保持身份的移动可继承；换页、替换、ID 复用及不明遮挡不继承有效性。

视觉 cache 不是通用语义存储。当前 pin 没有完整的模型标定及任务注意策略协议，
继续由 Mirage VisualScene 持有产品语义，Mirador 负责其视觉实体、缓存和跟踪。
将来经公开 Adapter 传递绑定句柄或选择条件，不把模型 label 写成 OCR/平台 role，
不在 Mirage 复制一个视觉跟踪器。每次被复用的证据保留原识别/标定时间。

### 4. 注意策略影响识别预算和通知，重要性与置信度分离

以下是待冻结的逻辑字段，不是已注册工具或上游 API：

- 身份：task/source/session、场景/authority epoch、policy revision、有效期。
- 焦点：对象引用优先，允许窗口锚定 ROI、文本/类别条件和关联对象；滚动后重新
  解析，失配不能继续使用旧坐标。目标数量、ROI 面积和条件复杂度均有上限。
- 权重：任务重要性、识别优先级、通知阈值与最大证据年龄；权重不得修改视觉置信度。
- 预算：区域/候选/时间预算，焦点外巡检与公平配额，过载降级及策略撤销结果。

策略在昂贵 OCR/YOLO 前生效；不能完成全屏识别后只过滤返回值。连续忙碌的焦点
不得永久饿死外围巡检。通知采用有界合并/迟滞；阈值、最长静默时间和预算在
M9-18 冻结。焦点切换先给出当前状态及每区域年龄、coverage/pending，再按需要
补新识别，不能把旧缓存作为“立即获得全新完整观察”。

Mirador 衡量变化幅度、稳定性和证据可靠性，按宿主策略执行选择；任务意义及
权重来自 Mira/Mirage。宿主强制保留权限、接管、屏幕源变化、模态遮挡与输入焦点
屏障，模型不能用低权重关闭这些守卫。

### 5. 放宽全屏变化耦合，保留目标局部动作门控

通知门控决定是否要求模型重新决策；输入门控决定一次输入能否安全派发。两者
分别配置和验收，不因静音通知就延长引用或降低动作证据标准。

| 新观察 | 模型侧 | 输入侧 |
| --- | --- | --- |
| 无关动画/时钟/pet 动画，目标及依赖无变化 | 合并或不通知 | 经当前局部证据验证后可继续；不凭整屏不同就拒绝 |
| 目标身份保持的移动/滚动 | 更新位置，按任务策略通知 | 重新定位、唯一性/接收窗口/变换/遮挡检查后继续 |
| 目标内容改变、文字未完成识别或证据过期 | 发布相关增量或补观察 | 有界重验；不确定时拒绝，不静默使用旧坐标 |
| 模态弹窗、焦点/源/权限变化、人类接管 | 及时发布屏障事件 | 阻止受影响输入，取消或安全收敛在途键鼠 |

全局 scene revision 因普通背景更新而增长，不应自动变成全局 authority epoch 变化；
M9-05/19 须审计当前 image_scope、像素守卫、目标引用与 epoch 的耦合，建立目标及
依赖区域的版本证明。旧客户端和原始坐标工具保持原守卫，不能直接删掉差异检查。
连续拖动还须保护路径与接收端，不能只检查起点。按
[DEC-056 2026-10-20 分层修订](DEC-056-post-action-verification.md)，普通完整输入
不默认附加逐动作业务条件或强制 OCR/新帧硬门禁；按动作组、状态依赖和任务边界
消费新观察，复用仍有效的同源证据，不另起同一问题的验证请求。显式业务条件只
阻止其依赖步骤，执行/释放不确定性与权限等安全屏障独立保留。缓存命中、预测和
“新帧到达”都不等于任务成功；省略业务验证也不延长旧引用有效期。该策略已随
DEC-056 接受，其分层门控 v2 首增量已接入会话工具；连续感知及目标局部门控能力
仍待各自工作项实施，不以该首增量声明背景感知已交付。

### 6. 资源有界：保留当前状态，不积累视频历史

2026-10-22：依 DEC-091 推进的 opt-in 采集宿主，局部 owner/需求代际、两代像素
预算、失败与零拷贝适配契约见[基础层设计](../design/continuous-capture-infrastructure.md)。
仅作为 M9-06/07 实施增量；本决策的生产策略、平台共存和性能门禁仍保持 Proposed。

候选存量为每源一个在途帧、一个最新待处理帧及必要基线签名/局部证据；平台
buffer、GPU、额外核验帧、旧代快照及模型图像也纳入总预算。仅用 mailbox 限长
无法约束消费者持有的共享引用，须同时约束存活代数与字节。无录制需求不保存
逐帧 PNG、artifact 或无限 patch 链。

3840×2160×4 字节的紧密 RGBA 帧约 31.6 MiB，两帧约 63.3 MiB；30 fps 每帧一次
整屏复制约 949 MiB/s，尚不计格式转换和额外读写。这是容量算术，非实测。
“只存增量”减少存量，不自动减少采集/比较/拷贝 CPU；delta 压缩/重建本身也有成本。
优先复用平台帧/可用 damage 和 Mirador 紧凑签名，仅在实际需要时复制/编码 ROI。

跳帧后 damage 合并覆盖自已提交视觉基线以来的变化；感知提交基线与模型发布
基线分开管理。未发布增量必须累积或按当前状态重新求差，不能因内部已更新而
漏通知。damage 集溢出、基线不明、尺寸/变换变化时显式 reset，有界全量恢复。
当前 `PerceptionSession::analyze_change` 相对其上一次分析输入维护签名，不直接
证明昂贵识别已提交；其结果须按上述基线规则消费。

一个源一个串行 perception owner，使用既有 kairo blocking worker；后台帧/最新
策略经 LatestMailbox，快照经 DoubleBuffer，订阅经 Topic；逐条不可丢的控制/结算
采用有界 MpscChannel 或现有 future admission 路径。Mailbox 不传裸 patch，除非
payload 已覆盖自提交基线以来的全部变化。通道拒绝、drop 和 CommStats 经现有
事件面可见；平台回调只校验/投递。有限任务消费 future，定时按已有 timer 能力，
不创建独立调度器。每进程唯一 Executor owner；停止生产、取消、唤醒阻塞、回收
worker、结算有限任务后，外部非 worker 执行 shutdown。

采样/识别/发布独立限频，静止退避；过载保留最新状态、合并区域、降低背景采样，
已接纳动作/等待必须显式结算。先在 M9-07/18 冻结按设备等级的字节、候选、时间、
公平配额和延迟门槛，再实测；不以显示器刷新率作为 OCR 或模型调用频率。

### 7. 按消费能力选择最低可用画质

2026-10-19 维护者补充：不要求高画质，允许在 LLM 特征理解及 OCR/YOLO/Tracker
识别可用的条件下尽量降低分辨率与画面质量，优先降低 CPU 和内存。该要求作用于
机器感知链路，不改变 DEC-108 的 pet 素材分辨率/播放质量。实现及默认档位仍待
M9-06/07/08/12 冻结与验收。

采用低清整屏巡检/模型概览、局部跟踪及按需清晰 ROI 的多尺度路径；不常驻多份
完整金字塔或要求所有消费者使用同一分辨率。小字、小图标和相似目标必须纳入
质量下限，低清不足时从当前源帧取得更清晰 ROI；不能放大已丢失的细节充当恢复。
具体候选、成本及轻量无人机方案见
[调研记录](../research/2026-10-19-lightweight-tracking-and-adaptive-perception.md)。

优先平台可用的源缩放/ROI/共享帧，随后复用 Mirador 裁剪/缩放/变换。源端只能
提供完整帧时报告完整成本，不把采后缩图宣传成采集开销下降。格式转换、派生
缓存、推理张量和 GPU 计入总预算；表示档位变更须重建相关比较基线/模板和坐标
映射。尺度与预处理进入缓存身份，语义绑定按原依赖校验，不因表示改变伪造新证据。

压缩文件质量与工作像素分辨率分别控制；本地不增加无益的有损编码/解码循环，
模型传输格式变更须先核对公开契约。灰度限于支持它且不依赖颜色的路径，现有
RGB 模型和固定张量契约保持。低清阈值由关键文字正确率、小目标召回/定位、
跟踪身份、模型 grounding/完成率与错误输入联合验收，不能只凭置信度宣布可用。

跟踪优先复用 pinned Mirador NCC/PSR/运动补偿与可选 NanoTrack backend；仅为当前
任务相关目标投入局部搜索预算，丢失/低置信再受限重检测。已有参考后端不等于
真实权重质量或速度已验证；不引入 OpenMV/OpenCV 等第二套视觉实现。量化/模型
替换须另经依赖公开能力、模型身份/缓存、供应链与目标设备质量回归核对。

### 8. 事件生命周期、时间对齐与按需理解

以下为 M9-05/07/08/18 待冻结的逻辑契约，不是现有 VisualScene 或 Mirador API：

- 实体携带 source/session、场景代际、stable ID + incarnation、内容/位置版本、
  首次/最近观测时间、实际识别时间和 coverage/pending。身份不确定、遮挡、丢失
  与确认消失分开；未处理区域不能产生“已消失”事件。
- 通用视觉事件覆盖出现、内容/位置/空间关系变化、遮挡/丢失/重捕获和确认消失。
  携带 event ID/sequence、实体与基线版本、证据时间窗、来源及质量；持续事件按
  开始/更新/结束组织，失效或源重置显式终结。具体事件词表及稳定化规则由上游
  契约评审，Mirage 只关联 task/action/request，不复制通用检测算法。
- 源捕获时间、识别完成时间、状态提交和事件发布时间分开；跨时钟记录映射质量，
  不以接收时间冒充捕获时间。动作关联以源帧水位和实际证据时间窗为准，不能仅凭
  时间相邻宣称动作引发了变化。迟到 OCR/跟踪/VLM 结果均校验来源、代际及版本。
- 日志按事件数、字节和保留时长共同限额；与当前快照分别设预算。淘汰后暴露
  gap/最早可用 sequence，消费者重建当前状态，不伪造完整历史。已接纳动作/等待
  的结算走独立可靠路径，不能随背景事件合并或淘汰。

重要状态变化、语义歧义或显式任务需求才升级 VLM；可由本地已知条件确定的事件
先直接推进等待/核验，无需每个关键事件都调用模型。请求优先携带当前文本状态、
相关事件与 ROI；确需时序解释才选取有预算的关键帧/局部时间窗口，带真实时间、
缺帧及覆盖说明。窗口证据不可用时返回不足并补新观察，不无限回溯或虚构前史。

VLM 请求按 source/task、事件范围、证据版本和策略版本去重、合并并限流；有界
在途数、期限和冷却由 M9-18 冻结。模型忙时积累相关差分，普通变化不反复打断或
重新发起同义请求；关键屏障仍立即阻止输入。拒绝/超时/取消/后端不可用显式返回，
不静默重试；模型无关或过期的解释不覆盖当前状态。短窗关键证据计入第 6 节总
预算，不转化为常驻视频历史；长期视觉记忆另行立项。

机制参考分为两部分：视觉侧由 Mirador 复用证据、筛选区域，Mirage 对概览/ROI/
关键帧与结构投影设预算；真正的学习式视觉 token 重采样属于模型内部能力，
不在 Mirador 仿造不可供任意 VLM 消费的 embedding，也不将 ROI 筛选冒称为
Resampler。时序侧按共同时间轴组织带显式边界的观察—变化—动作反馈单元，
保留各项时间窗/水位、缺失及版本，由 Mira 在有界推进点消费；是否升级理解
与内容解释分开。窗长和合并规则在 07/18 冻结，不照搬 MiniCPM 的实验频率。
该方式借鉴 TDM 的分组/交错原则，不创建新调度器；普通请求式模型仍在下轮
消费最新单元，不能据此声称支持生成期间注入视觉 token 或 Omni-Flow 全双工。

开发优先级为：增量状态与基线（05/06/07）→跨帧身份与视觉事件（08/18 的通用
契约部分）→任务注意与按需 VLM 解释（13/18）→有独立预算/保留策略的长期记忆。
已有 13 的基础绑定可并行，首个可验收视觉状态增量不依赖额外 VLM。动作闭环
继续按 09/10 推进，不强制等待 tracker 或模型机制实验。

## 验证方式与限制

- 共存：真实 compositor 上 pet 连续动画、气泡/阴影、多屏/DPI、移动路径及原位置
  底层变化；截图像素与输入命中均核对，记录闪烁/黑洞、动画间隔与尾延迟。
- 感知：静态/微小文字/密集文字、无关动画、滚动、弹窗、焦点切换和模型推理期间
  变化；少识别/少通知时仍保持状态覆盖，partial/pending 不当作消失或未变化。
- 语义/门控：无关变化零重标定；替换/ID 复用/晚到不误绑定；目标移动局部放行，
  模态拦截/接管及时阻断；动作后新证据和一次派发回归。
- 资源：1080p/4K、多源、慢消费者/旧快照钉住、长时运行及取消/关闭；测 RSS/GPU、
  总拷贝字节/带宽、CPU、backend 实调数、帧年龄与通知 P50/P95、pet 呈现间隔。
- 配对 A/B：固定任务/模型/页面，比较完成率、错误输入/漏事件、延迟、模型往返、
  图片与 token，联合本地资源判断收益。阈值预登记，ASAN/UBSAN 与跨上下文 TSAN
  按实现阶段运行；无目标设备/权重/授权环境时不关闭相应门禁。
- 事件与升级：静态/动画无重复语义请求；相似实体不串 ID，短暂丢失不误报消失；
  事件开始/更新/结束、日志淘汰 gap、源重置及乱序时间均可重放。M9-12 对比固定
  周期识别基线与增量方案的事件漏检/延迟、CPU/RSS/GPU/拷贝和 VLM 实调数；
  首阶段关闭额外 VLM 仍可维护状态；分别测试视觉表示预算、时间单元合并及晚到
  输出重验。不要求为了对照而在低端设备部署大型 Video-LLM。

本轮仅完成文档/API/issue 核对与静态检查，没有实现连续采集/移动或修改产品默认值，
没有运行上述基准。负责人 Mirage 维护者；补跑条件为 M9-06/07/13/17/18/19 接线完成、

## M9-07 首个实施边界（2026-10-20）

VisualSessionHost 增加调用方显式选择的后台变化门控。只有非关键后台巡检可以选择
`when_changed`；相对最后成功完整分析基线的 `kNone` 时，整次昂贵分析不执行
并返回独立 skipped 终态，
不发布空快照、不把旧快照改成当前证据。默认仍每次执行；动作守卫、核验与模型
观察沿默认路径，OCR/检测 Refresh、模板登记和 marks 请求强制执行。
门控要求启用 change analysis，首帧/局部/全局变化均执行；取消、期限、拒绝和
shutdown 沿同一 Executor 生命周期。此近似后台筛选不是像素精确一致性判据，
不供当前动作引用或目标值核验。该增量不创建常驻 producer，不启用尚未交付的
持续前台采集或 pet 共存承诺，M9-07 保持 In Progress。

门控通过 Mirador 公开签名/差分 API 比较，不自研识别算法。每源额外保留一个
64×64 灰度签名（4096 字节），本次比较另有一个等大临时签名；不持有整屏副本。
固定关闭 dHash 提前退出，沿默认 block 阈值比较；这是近似筛选，颜色/小文字
不能由灰度巡检证明未变。跳过不推进完成基线，防止连续微小变化被邻帧比较吞掉；
失败/取消/超时/非后台执行清除该基线。当前帧的相邻变化报告与后台 admission
报告及其基线 sequence 分开保留，不伪造 Mirador 已提交快照的变化来源。

后台请求还必须声明非零 analysis_policy_revision；可信宿主在阶段参数、目标位置
或授权改变时推进版本。跨版本强制完整执行，避免旧配置的无变化结论抑制新需求。
真实后台消费者、静态退避与端到端节省仍需后续接线和验收，不能据此声称当前
生产 OCR/检测调用已经下降。
