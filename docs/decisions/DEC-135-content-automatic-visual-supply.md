# DEC-135：内容任务在既有模型请求中自动携带稀疏拼图

> 状态：Accepted（维护者要求减少LLM获取截图请求次数）
> 日期：2026-10-29；负责人：Mirage维护者
> 关联：M9-30/29/24；DEC-132/133/134

## 决策

content 1.1.0的begin增加可选auto_storyboard布尔值，默认false保留原手动行为；
内容观看提示推荐显式true。声明后，既有ModelInputSupplier在locating/observing
阶段按需从现有缓存选择2–4张新帧，生成既有低清拼图并随当前已存在的模型请求
供给，不再要求先请求storyboard/event_frame/capture。不启动新的模型请求或采样。
范围/声音与自动模式在本turn不可隐式切换，同配置begin幂等，中断后显式重开。

复用DEC-134的30秒观察时间窗、最多4帧；仍只有8预览/256事件，320格/640²、
无音频、不代表完整视频。无2张新帧则不足，不轮询/补帧。每次自动构建尝试间隔
至少5秒；Completed消费后也至少间隔5秒。时间检查只在既有supplier调用中进行，
不是私有timer/调度器。未消费的图片保持原工件供重试，不重复编码；显式待供图
优先，文本精读/低预算时不构建自动图。评估完成或不足后停止自动供图，来源/
权限/gap中断后停止，显式重开才恢复。

自动图片仍是历史观察，不能用于桌面输入或动作验证。选择自动模式即允许实际
供图时退役此前的图像/输入临时引用；metadata明确披露，后续输入必须通过原
新鲜capture/动作路径取得引用。未消费的显式图片不被自动替换。未开启自动模式
保持原工具行为，不基于任务文本关键词强制启用。

共享原拼图打包、内容引用、请求guard/Completed账与ACK路径。失败、Incomplete、
缺图/预算扣留不算消费；源/权限/ABA和旧请求不得录入。自动失败/不足原因随
现有连续观察提交，不吞失败、不改变Mira生命周期；不添加重试循环。

## 承载与预算

核对Mira公开ModelInputSupplier：同步、有界、每个既有请求调用一次；复用该hook，
不修改ConversationLoop，不新增worker/队列/后台请求。Mirador继续承载resize，
Mirage只做产品证据选择/供给；不修改pinned依赖。共享单图artifact槽，无额外
像素缓存；仅增加一个下次允许时刻和有界原因，诊断≤256B，整体观察仍≤8KiB。

本增量减少的是模型主动取图工具及其往返，后台CV采样频率不变；不把工具成功、
供图或时间间隔当语义理解。受控同一两帧问答比较手动begin→storyboard→assess
和自动begin→assess，核对模型调用、取图工具次数、图片数量与内容证据相同。
真实LLM主动使用率、token/计算收益和内容质量另验，不保证模型总能正确声明意图。

## 验证

时间门禁使用可控单调时刻验证，不引入真实5秒sleep；真实supplier测试静态去重、
失败/预算/显式图片优先、ACK失败、评估停止、来源/权限/取消与重开、图像预算/
引用退役。ModelLayer受控自动流程及手动对照验证减少往返，最后执行相关配置
回归并同步计划/设计/示例。M9-30整体继续In Progress，播放器/声音与真实质量开放。
