# DEC-090：长程任务持续执行与有界资源管理

> 状态：Accepted（2026-10-15 维护者确认分析方向并要求形成决策与计划）
> 日期：2026-10-15
> 负责人：Mirage 维护者
> 冻结里程碑：M9-02/03/04；公开依赖 API 由 Mira 上游冻结
> 替代/被替代：部分替代 DEC-085 的最终轮关闭策略、DEC-087 的固定轮数包络；扩展 DEC-088

## 背景与问题

2026-10-15 的任务在 16 个模型步骤后以 MaxTurns 结束，最后一轮工具被关闭，
模型没有可靠的收尾机会。上下文压缩不能解除模型步骤上限；增大为 64/128 也
只是推迟终止。调查证据及本地 ZCode 对照见
[分析记录](../analysis/session-budget-and-native-pet-regression-20261015.md)。

ZCode 主循环持续推进，步骤/工具次数用于统计和异常提醒，上下文由 compact
处理；单次请求、失败恢复和输出续写仍有边界。这与 Mirage 长程任务目标一致。
调查时 pinned ConversationLoop 尚无公开的无累计次数限制模式，缺口为
[MIRA-20261015-002](../dependency_feedback/mira.md#mira-20261015-002)。

## 决策

1. 正常主任务默认不因累计模型步骤、工具调用次数或执行时间长而终止。不将新的
   默认总 token/总时长上限作为替代。计数保留为诊断；用户显式设置的预算具有
   独立来源、单位、耗尽结果和恢复语义，不默认虚构用户预算。
2. 移除第 15/16 轮强制收尾和 final-turn 工具关闭策略。结束依据为目标完成、
   用户取消/接管、权限变化、真实不可恢复错误或有证据的无进展状态。重复失败
   应先分类、有限恢复或报告阻塞；“调用很多”不等于无进展。
3. 持续的是任务生命周期；每次推进是有界工作单元。模型请求、工具、观察、等待、
   失败重试和输出续写各有期限或预算，且取消/关闭能解除等待。所有调度由 Runtime
   唯一 owner 的 kairo 承载，不创建私有线程、队列或调度器。
4. 内存、队列、缓存、活动操作与未结算句柄始终有界。已结算动作归档，模型历史
   压缩，帧保留固定窗口；未确认副作用不得因容量压力被淘汰。活动容量不足须
   明确背压/拒绝，不得将累计第 N 个动作当作主任务终止条件。
5. 每次模型准入携带真实有限的请求预算，累计实际用量单独统计。替换固定 22 倍
   整轮包络；不得传无限值/整数最大值绕过准入，累计计数及算术不得溢出。
6. 保持当前 Task/Session ID、取消上下文与生命周期 owner。暂停/恢复遵循 pinned
   MiraRuntime；恢复前重观察，未确认动作只允许观察/核验，不重发输入。已完成、
   失败或取消的任务不复活，不反复新建 loop 从原请求重做任务来伪装持续运行。
7. 上下文以完整请求为预算对象：system/目标、会话、观察、工具 schema、历史、
   图片、输出和安全余量统一计算，优先复用 Mira ContextManager。保护目标、约束、
   最近完整工具组及待核验动作；多 tool call 与 thinking 的协议组必须完整。
8. 上下文窗口来自已验证模型元数据或显式配置；别名不能猜测窗口。未知窗口的
   产品状态必须可见；仍限制本地历史存量，但不能声称已执行基于真实窗口的
   preflight。压缩后重新校准 usage 锚点，不让旧大输入值持续挤压输出。
9. 实际停止原因用稳定结构化结果表达；保留已验证进度、剩余目标和恢复条件。
   有条件时作有限文本收尾，否则用宿主事实摘要。摘要不是成功凭证；部分输出、
   输入已发送或工具准入成功都不等于任务完成。

## 依赖与契约冻结

先处理 MIRA-20261015-002，再消费公开的持续循环或可推进/可恢复同一循环契约。
`max_turns=0` 在当前 pin 不是不限；不能直接修改 third_party。具体 API、准入
记账、历史存量与退出结果在 M9-02 冻结，Mirage 接线在 M9-03 实施。

无进展检测依据动作/观察摘要、失败类别和待达目标，不能只比较整屏截图摘要或
参数。提醒、有限恢复、等待外部条件和停止的判定表在 M9-01/03 冻结；阈值不在
本决策中猜定。显式预算扩展如需新增 IPC/UI，由 M9-03 同步 schema 与 golden。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 提高模型步骤/工具总上限 | 仍会截断正常长任务，不采用 |
| 每到上限就新建 loop 或任务 | 私有历史、动作状态与副作用连续性无法保证，不采用 |
| 取消所有容量、超时和失败恢复边界 | 无法保证取消、关闭和资源可控，不采用 |
| 持续主任务 + 单次有界推进 + compact | 采用，复用 Mira/kairo 能力 |

## 影响与风险

修订 DEC-085/087 中上述局部策略，其网络恢复、输出截断分类、每调用输出声明和
取消纪律继续有效。DEC-088 已实现能力保留，未完成端到端项迁入 M9，不继承完成
结论。上游缺口阻塞持续循环接线，不阻塞本地视觉与 pet 独立推进。

持续任务需要验证长期内存和存储增长；“不按步数终止”不承诺无限物理存储。
保留任务事实的归档/检查点与模型可见上下文分开，错误不可被压缩隐藏。

## 验证方式

按 M9 测试矩阵验证超过旧 16/32 与候选 64/128 上限的正常任务、长期容量平台期、
多工具协议、compact、输出续写、拒绝、取消、超时及 shutdown。有限测试只证明
相应长度；无计数停止的声明还须由控制流与配置审计支持。真实 provider/目标平台
未运行不得声明长程或跨平台验收通过。
