# DEC-101：取消默认会话数量上限与逐会话 JSON 存储

> 状态：Accepted
> 日期：2026-10-18
> 负责人：Mirage 维护者
> 冻结里程碑：M6
> 替代：DEC-021、DEC-046 中的默认会话数量及合并存储约定；其他条款继续生效

## 背景与问题

维护者要求取消会话个数限制，并将不同会话存入不同 JSON。原生 24 个、服务默认
25 个及旧文件解码 64 个的限制相互叠加，所有历史还共享一个 8 MiB 文件预算。
已核对 pinned Mira 的 core-runtime、state_store.hpp 和 json.hpp：其运行状态机与
checkpoint 存储不提供 Mirage 产品历史 JSON 布局；此变更属于产品持久化层职责。

## 决策

- 原生界面不再限制会话个数；切换会话释放旧线程高度/布局缓存，只保留当前线程缓存。
  ServiceConfig.max_sessions 默认 0，表示不限制数量。
  非零配置继续显式拒绝超额准入和不完整恢复。逐会话历史、输入、IPC 与执行预算保留。
- 每个会话位于状态目录的 sessions/<32位小写十六进制ID>.json，沿用 schema 1
  编解码，但文件仅含本会话。8 MiB 限制改为每文件；不设全局会话计数上限。
- 删除通过原子写入空 sessions 数组的墓碑提交；不在重启时复活旧历史，失败时旧文件仍可
  恢复。独立文件逐个原子保存，不承诺跨会话事务。未变化的会话文件不重写。
- 启动兼容旧 session-state.json；迁移成功前旧文件是事实源，所有会话文件写完后
  将其原子替换为固定 schema 2 存储标记。新格式启动扫描 sessions/，忽略临时文件；
  文件名和内部 ID 必须一致。无历史的内部主会话继续不保存。
- 单个损坏会话不影响其他会话恢复，并保留原文件；损坏旧合并文件禁用写回以保护原数据。
  迁移和文件 I/O 继续由既有调用上下文与 session_state_mutex 串行化，不新增并发设施。

## 备选方案

仅扩大固定数量仍不满足要求；继续合并存储仍共享文件预算。全局会话索引引入额外一致性
与容量约束，因此采用目录扫描与逐会话原子提交。

## 影响与风险

更多会话增加启动扫描、内存及 session.list 响应开销；不宣称无限资源或性能保证。
删除保留小型墓碑文件；迁移后旧版本不能读取 schema 2 标记，回退需事先备份旧文件。

## 验证方式

覆盖超过原有数量、逐文件恢复、总历史超过旧全局字节预算、迁移中断/重试、文件损坏隔离、
文件名校验、删除/重启、保存失败和既有编辑回滚。Linux Release 与消毒器定向执行；
Windows 与真实 GUI 的未执行部分明确记录。
