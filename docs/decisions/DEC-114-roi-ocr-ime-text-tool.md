# DEC-114：ROI OCR 输入法文本工具

> 状态：Accepted
> 日期：2026-10-23
> 负责人：Mirage 维护者
> 冻结里程碑：M7-35
> 替代/被替代：无；细化 DEC-110 M7-28

## 背景与问题

维护者要求将输入法使用封装成完整工具：Mira 指定输入框及文字，工具自行输入、识别、
翻页和选字；识别只用 ROI OCR，不用 VLM，并通过重复测试统计成功率。最新本地会话
只查询了环境/引擎，没有实际选字；引擎名也不能证明目标框当前的中英文状态。

## 决策

首增量提供 `desktop.input.fill` 1.0.0：指定当前交互截图的输入框 ROI、目标文字，
并提供 mode_roi 与 candidates_roi 定位约束。工具内部所有模式、候选和落字识别均
裁剪到对应 ROI 后调用现有 Mirador OCR；不向模型发送这些截图，不允许模型替代
OCR 判断。先作为复合 Builtin Tool 实施，不重复实现 Mira 的 Workflow/Skill
发布体系；后续有经验证固定 Workflow 时可沿 pinned Skill 通道发布。

语言规划与视觉识别分开：可在任何副作用前通过已有 ModelGateway 做一次纯文本
拼音规划，只允许目标字到 ASCII 拼音的结构化映射，不提供图片、OCR、工具或桌面
内容。规划必须逐段精确覆盖原文，通过 UTF-8、字符/长度和拼音约束后才能执行；模型
不能选择数字键或解释候选。该请求沿原任务的准入、取消、deadline、用量和事件。

工具本身为有界显式状态机：原有目标守卫与自然点击聚焦 → 确认模式/无未决候选 →
完整按键清空目标框 → 按汉字词组/ASCII 段输入 → ROI OCR 精确匹配候选及本页编号 →
候选在两张新帧一致后按配置 = 翻页 → 数字选字 → 目标 ROI 核对累计已提交文字。模式改变用一次完整
Shift 点按并重新 OCR 确认。没有文本/候选证据时失败，不猜测数字、不用剪贴板，
不把预编辑或候选正文当落字。仅观察可有最多三次严格新帧复读以等待界面刷新；
输入/切换/选字动作不自动重发。工具不执行 Enter 表单提交。

默认 replace，首增量只支持短基本汉字与可打印 ASCII，最大 32 个字符/256 UTF-8
字节、每段最多 8 页、最多 256 次内部动作、总协作预算 120 秒并受父任务更短期限
限制。不能识别、多音字规划错误、候选缺失/页重复、焦点/源/授权变化、取消及
释放失败均停止；返回已验证前缀计数与失败阶段，不自动重放整段。更长文本需上层
拆分并在后续契约中定义追加语义，不能静默截断。

目标值只接受一条完整 OCR 行，保留空格，不以合并分框代替精确值证据。
候选文本框的通用行合并/排序复用 Mirador `merge_text_lines`；IME 层保留原框
置信度并解释编号/候选语法，不重新实现通用视觉后处理。

复用既有 ActionCoordinator、完整输入、共享采集 session、Mirador crop/OCR 和
外部 Executor owner，不新建线程、队列或 Agent 循环。初始聚焦沿旧输入守卫完成；
后续整个复合操作持有单写者 lease，聚焦与持 lease 之间的 epoch 必须连续，否则
停止。每个有副作用步骤重新检查原任务/权限/authority，输入结果必须释放。

## 影响与风险

首接线限定已有 interactive shared-session 后端；不暗示全部 X11/Windows 暴露该工具。
ROI 参数是同一截图坐标系，候选与最终输入框 ROI 不得重叠，避免候选文字造成假成功。
OCR 置信/编号模糊、输入框排版或占位符、候选窗换位及用户操作可能造成明确失败。
拼音规划优先常见 2～8 字词组（每段最多 64 个拼音字母），兼容单字。规划是语言生成，不属于视觉识别；其准确率应与 OCR/执行成功率区分统计。

## 验证方式

覆盖候选编号重排/重复页/低置信度/错误落字、无 VLM 图像输入、ROI 尺寸检查、预算、
异常、取消/撤权/释放、准入拒绝与关闭。重复受控工具链与真实输入法/真实 OCR 试验
分别记录样本、完整成功/失败/不确定及错误接受数，禁止将 mock 成功率称为真实成功率。
真实系统授权无法自动完成时保留该平台门禁，不以模拟授权冒充。
