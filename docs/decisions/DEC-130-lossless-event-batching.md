# DEC-130：普通事件的无损批次表示

> 状态：Accepted（按维护者继续M9授权，实施M9-29第二增量）
> 日期：2026-10-28；负责人：Mirage维护者
> 关联：DEC-121/129；M9-29/18

位置与外观变化在现有公开事件中共同表示为position_or_appearance_changed，
不能凭同一文字/框就推断外观语义没变。本阶段不删除中间变化，而在单次模型供给
压缩重复字段：连续、同来源/身份/实例/类型/文本、已确认、严格递增cursor及
非倒退时间、跨度≤1秒的此类事件最多8条组成一行（帧序号非零且不倒退，resync时禁用）。该行保留末条的现有平面字段，
这里的无损指保留原模型供给可见的事件字段，年龄仍以毫秒表示，过期帧ID仍为空。
prior_samples按时间顺序保留此前各次cursor、帧序号/可用ID、年龄及完整框，
sample_count明确条数；公共字段适用于所有样本。不会合并文本、关系、出现/消失、
来源重置、未确认区域观察、媒体关键帧，亦不跨这些事件、gap、实例或来源屏障。

装配仅在既有单次supplier内读取已有有界日志，不等待聚合窗口，不新建定时任务、
生产队列或缓存。原始journal与256条/256KiB、8帧历史不变；每次仍≤16输出行、
事件JSON≤7000B、完整供给≤8192B。预算不够时缩短当前组的前缀或停止，最终按
实际呈现的连续前缀末cursor提交ACK；不跳过未呈现的事件。请求未完成不消费，
重试可再次供给。8KiB末端裁剪仍删除整行，不把部分组误当已消费。

这是表示压缩，不是语义过滤、视频覆盖、视觉证据重用或在线token/完成率收益证明。
单次供给可在相同预算内包含更多已发生变化；逐次信息保留，LLM仍须看所有需要的
prior_samples。只有当前已有日志被批次化，不在模型生成期间注入事件。多目标
重要性与真正按语义去噪/唤醒策略仍属M9-29后续。

验收：逐样本字段无损还原、不同身份/来源/文本/确认/时间/gap/关键事件断组、
最多8样本/16行/7000B与外层8KiB、预算前缀/ACK/失败重供给、真实supplier接线，
五配置增量回归及格式/公开边界；源码/失败/未执行范围单独记录。

实现及实测见[验收记录](../compatibility/lossless-event-batching-20261028.md)，
输入解释见[批次示例](../examples/lossless-event-batching.md)。
