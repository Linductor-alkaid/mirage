# DEC-122：实验性媒体识别延后与未知证据投影

> 状态：Accepted（维护者授权推进 DEC-121 / M9-26）
> 日期：2026-10-28
> 负责人：Mirage 维护者
> 冻结里程碑：M9
> 工作项：M9-26；关联 M9-25/28/30/32/33
> 替代/被替代：无；细化 DEC-121，生产默认仍关闭

## 背景与问题

pinned Mirador `ContinuousPerception::plan_cycle` 公共头要求 frame 是 snapshot
实际融合所用帧（1211行附近）。因此不能改旧快照的 frame_sequence 后，将它
作为新帧交给 plan/accept 来证明 reuse；空融合同样可能使旧对象消失。当前公开
指纹/patch fingerprint 是降采样表示，不能证明单字符或原图 ROI 完全未变。
精确跨帧复用仍按 MIRADOR-20261027-001 核对，不另写通用跟踪/哈希算法。

## 决策

1. 先交付保守实验：`--experimental-recognition-refresh-ms N`，0 为关闭，
   有效实验范围100～5000ms，建议试验起点2000ms。该值只是强制重识别的调度
   间隔，不是事件完整性或证据最大延迟保证；识别耗时另计。M9-33 前不切默认。
2. 完成同来源/策略的识别 bootstrap、已有对象均确认、媒体区域已确认后，先
   用 M9-25 sample_only 比较相邻与累计变化。只有两种报告的变化区域都完全
   落在媒体范围、且未到强制刷新期限，才延后 OCR/detector。区外变化、源/尺寸/
   焦点策略变化、未确认实体、过期和重新 bootstrap 均走完整识别；前台显式
   OCR、动作验证不受节流。阈值化 CV 可能漏微变化，记录该实验的缺口窗口。
3. 延后周期返回 recognition_deferred，保留相同对象ID/实例的历史文本，但所有
   对象为 pending/未确认，不签发语义标注引用，不宣称 validated reuse。不推进
   Mirador 的融合/覆盖/确认/消失状态。首个延后周期推进产品内容失效版本，使
   旧 LLM 标签不能跨未知区间自动恢复；后续延后不重复改内容版本。
4. scene_observed_at 保留原识别时间；deferred_frames 单独计数，不增加 analyzed
   识别计数。模型得到延后标记、原因及原年龄。历史对象不因跳识别而被删除。
   达到刷新期限时，即使 CV 报告不变也强制真实识别，不能由跳过周期续期。
5. 延后仍保留节流媒体关键帧；不制造语义 appeared/disappeared。恢复识别使用
   同次 capture 的已拥有像素和新的分析序号，不再 capture；拒绝、失败、取消、
   超时和源/策略不匹配明确可见，不缓存失败为成功。全部沿用现有 kairo owner、
   worker、mailbox/Topic，未新建并发设施。

## 备选方案

- 将旧快照作为当前融合证据：违反 plan_cycle 的来源契约，拒绝。
- 在 Mirage 自写原图哈希/跟踪以声明精确复用：违背依赖职责，拒绝。
- 媒体活跃时永久关 OCR：会漏字幕/提示和积累过期状态，拒绝。
- 继续每变化周期 OCR：作为默认及实验失败回退保留，成本问题继续由后续阶段解决。

## 影响与风险

实验会推迟媒体字幕/瞬时提示识别，失效后的 LLM 标签需要重新标注；没有声称
完成精确复用、5/10Hz 跟踪或视频理解。配置有界但尚未经在线/低端 A/B冻结。
管道仅保存最多256对对象ID/实例等产品元数据，不增加整屏缓存；M9-28再解耦
慢识别上下文。精确复用、逐对象年龄与新候选识别仍保持开放。

## 验证方式

合成媒体上比较默认/实验后端实际调用数，验证未知对象不删除、识别年龄不续期、
旧标签不复活、区外/来源/焦点/期限触发识别、显式 OCR 不受影响，以及失败/取消/
拒绝/timeout/shutdown；Debug/ASAN/UBSAN/TSAN。CLI/运行配置接线、原生构建
及真实 OCR 控制实验分别记录。未执行的真实平台、在线内容质量和资源/token
A/B由 Mirage维护者在固定环境就绪后按 M9-33 补跑。
