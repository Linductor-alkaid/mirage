# DEC-149：原生工作流运行与显式恢复

> 状态：Accepted（M15-20 限定入口；完整资产审阅/自动恢复另验）
> 日期：2026-11-16
> 负责人：Mirage 维护者
> 冻结里程碑：M15-20；M15-08 首增量
> 替代/被替代：扩展 DEC-148，保持原服务预算与模型配置限制；入口布局由 DEC-150 替代

## 背景与问题

产品服务已支持显式恢复，原生窗口尚无工作流入口。用户需要在同一窗口看到目录、
运行及等待状态，主动请求恢复或停止，并分别确认 Run 完成与经验保存。

## 决策

- 扩展既有原生窗口，在会话标题栏提供「工作流 / 返回对话」入口；保留会话草稿、历史、
  侧栏和设置。沿现有中性明暗、Noto Sans SC、800px 内容列、860×620 最小窗口与滚动组件。
  不创建新窗口或另一套任务状态机。
- 页面显示服务当前目录、运行列表、所选运行的恢复结果和默认学习存储状态。可显式
  运行已发布且 runnable 的版本（默认参数），取消未终结 Run，发起/查询/取消单次恢复，
  在确认完成且恢复成功后单独保存经验。服务仍作最终准入与验证，按钮不构成权限。
- 独立、只在 UI 线程使用的投影模型保存有界快照和请求修订号：最多 128 个目录、256 个
  Run；一次只允许一组最多三项读取或一项控制请求。响应校验预期类型、操作、目标与
  修订；断线/事件缺口使快照失效，迟到响应不得复活状态。事件只提示刷新，不推测中间状态。
- 所有请求经既有 RuntimeBridge 的 Executor 串行请求/future、MpscChannel 和关闭路径；
  不增加线程、定时器、自动恢复、重试或轮询 worker。用户打开页面与显式刷新读取快照。
  控制请求接纳后显示确认，模型结算和 Run 终态分别查询；保存经验单独显示成功/失败。
- 等待、未加载、断线和过期快照禁用相关动作；失败保留已显示快照并明确过期，提供刷新。
  窄窗口动作换行，长名称截断只影响显示，真实 ID/请求绑定保持；错误可见，状态有文字。
  提示首次绑定恢复后模型配置固定至服务重启，不显示为可无缝切换。

2026-11-16 后续：[DEC-150](DEC-150-workflow-graph-composition.md) 将主入口迁到侧栏左上
「会话 / 工作流」切换，增加图编辑与独立调用；本决策的有界运行/恢复控制合同继续生效。

## 备选方案

将运行操作放进桌面资源设置会混淆任务和配置；新建控制台窗口会割裂现有入口。
自动刷新/恢复会引入额外任务生产者与隐式模型调用，本增量不采用。

## 影响与风险

入口不会恢复服务重启前的 Run 或目录，也不替代候选审阅/发布门禁。刷新采用显式快照，
事件期间显示旧记录并禁用动作；用户须再次读取。候选编辑/导入和自动恢复属于后续项。
公开 IPC 不变，不升级依赖或新增默认权限；合成 renderer/脚本模型不能证明真实应用
变化、在线质量或 Windows 运行结果。范围证据见
[专项验收](../compatibility/native-workflow-controls-20261116.md)。

## 验证方式

投影模型测试拒绝坏/错类型/错目标/迟到响应、快照上限、单飞、断线和过期动作；
真实 RuntimeBridge/隔离 RuntimeService 验证目录、实跑与恢复控制；现有服务专项保留
异常、取消、超时和关闭证据。原生 renderer 检查常规/最小窗口、明暗、侧栏收起、
等待/失败/长名称/终态，并捕获真实渲染图。Debug/ASAN/UBSAN/TSAN 分别记录实测范围，
未通过的平台或在线模型不记完成。
