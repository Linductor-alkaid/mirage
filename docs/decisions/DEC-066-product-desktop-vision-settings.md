# DEC-066：桌面视觉产品启用

> 状态：Accepted
> 日期：2026-10-11
> 关联：M7-12；DEC-011、045、057、058、064

## 决策

已交付的工具继续由 Runtime Service / Mira ConversationLoop 装配。新增
`vision.get` / `vision.set` 产品设置面，保存审核过的本地 OCR 清单路径到
`service.json` 的 `vision.ocr_manifest`；空字符串关闭。路径必须是绝对路径，
不超过 4096 字节且不含控制字符。设置读写沿用服务 owner 的 IPC 分发，不新增后台任务。

保存只表示持久化成功，资源身份、文件与权重校验沿用 DEC-057，在下次启动执行。
响应分别返回保存路径、当前启动路径、编译支持、管线运行状态和是否需要重启。
存储不可用或旧文件损坏时拒绝，不覆盖其他模型、权限与运行配置。CLI 清单覆盖
持久化设置，只作用于本次进程；原生页面明确展示保存状态与运行状态的差异。

产品托盘显式探测 X11、AT-SPI2、应用和通知 Provider，连接失败保持能力缺失；
不改变 LinuxDesktopEnvironment 的可选构造默认值。headless Service 保留原默认，
显式 OCR 清单会启用 X11 Screen 探测。

统一 `mirage start --ocr-manifest PATH` 向新托盘传递清单。指定清单时拒绝复用已有
服务，避免把未应用参数报告为成功。普通启动仍复用已有托盘。显式 `--ocr-manifest ""` 暂停 OCR，可在坏资源导致
启动失败时进入设置并清空/修正持久化路径；该覆盖也不得复用已有服务。新增独立
`native-vision-debug` / `native-vision-release` 构建预设；普通构建保留 OCR 关闭默认。
模型与字典不自动下载，不将临时验收资源加入仓库或安装包。

原生设置增加「桌面工具」页，提供清单路径、保存和刷新；模型「识图」配置沿用既有
入口。会话只读允许已注册的观察工具，禁止桌面修改；默认权限仍须通过既有权限判定。
页面不把资源清单已保存包装成视觉可用，不把 Xorg 的能力声明为 Windows/原生 Wayland
已交付，也不改变五秒引用、像素重验和输入释放纪律。

`desktop.observe` 的 OCR 失败沿用 `unavailable`，追加有界原因：取消/期限耗尽、
桌面 epoch 变化或 backend 错误。错误文本最多取 backend 消息的 512 字节并保持
UTF-8 边界；这用于区分启动可用与单次观察成功，不扩展观察预算。

## 验收

覆盖设置边界、IPC 编解码、合并持久化/读写失败、编译支持与重启投影、启动参数转发与
已有服务拒绝；复用已有桌面会话链路回归。真实模型原生桌面任务单独取证，未运行不记完成。

2026-10-11 补充：DEC-068 改变 Linux 原生产品的无设置默认值为包内资源；明确的
自定义/空清单和 CLI 优先、重启生效及恢复语义继续有效。普通 native 预设默认带 OCR
资源，瘦开发构建需显式关闭 OCR 和 bundle，不能用于产品打包。

2026-10-14 补充（M7-12 Windows 产品面）：本决策的宿主接线语义扩展到 Windows——
产品宿主此前以全默认构造 `WindowsDesktopEnvironment`，四个 opt-in 面（Win32
窗口/屏幕/输入、UIA、应用、通知）全部关闭，桌面工具链在 Windows 产品进程内
实际不可达。现在产品沿 Linux 分支同义传递 `product`：探测失败的访问器保持
null（fail closed，其余面存活），无头开发 service 保持原默认；产品进程输出
一行启动能力日志记录实际打开的访问器。取证与边界见 M7 计划同日验证记录；
原生「桌面工具」页与真实桌面任务的 Windows 产品预览由后续增量承接。
