# DEC-119：有限容量的记忆、会话归档与清理

> 状态：Accepted（容量与生命周期原则；具体算法、参数及契约待冻结）
> 日期：2026-10-27
> 负责人：Mirage 维护者；通用机制由 Mira 上游评审
> 冻结里程碑：M11～M14 统一交互实现前，具体预算/遗忘策略须先评审与验证
> 替代：DEC-101 的默认无会话数量上限和无全局计数预算原则；逐会话布局/迁移纪律保留。
> 同时修订持续个体路线图中“遗忘仅降低激活、原始经历始终可检索”的前提。

## 背景与问题

维护者明确：实际部署不具备无限存储，记忆系统必须选择性遗忘零星经历，管理中的
会话数也必须有界；已完全结束且不再使用的会话应归档并最终清理。
这补充了[统一交互需求](../plans/agent-memory-upstream-feedback-20261027.md)，
不是取消用户的单一输入口；内部数据生命周期由 Mira 管理，用户仍面对同一个 Mira。

当前 [DEC-101](DEC-101-session-files-and-unlimited-count.md) 的 `max_sessions=0`
和逐文件存储解决了旧固定数量/共享文件预算问题，但没有全局资源收敛机制。
路线图将低激活经历归档、保留全部原始记录，也只是转移增长位置。

## 决策

### 1. 所有层次均有部署预算

记忆条目/字节、受管理/驻留会话数、归档数量/字节/保留期、原始事件、上下文投影、
附件/截图/向量索引、版本/墓碑/幂等台账和受管备份均计入有限预算。
同时规定进程内与持久化总量、分主体公平份额、单对象大小和操作峰值。
不能以逐条上限、token 窗口或单次 sweep 上限代替总容量上限。

具体数值按部署档位与目标设备验收冻结；本决策不凭空给出 GB、天数或会话数。
软水位触发回收，硬水位控制接纳；明确保留控制/取消/回收所需预算及峰值预留。
回收赶不上写入、磁盘满、全为受保护记录时，拒绝/限流/等待必须有界且显式，不能
无限扩容或丢弃仍需保护的数据。接纳与容量预留须覆盖并发写入和重启恢复。

### 2. 设计分层遗忘，不保证永远保留所有细节

区分召回降权、去重/抽象巩固、有限归档和物理删除；每层有容量/时限与退出条件。
候选策略综合经验证的重要性、时效性、实际用途、冗余、可重获性、敏感性与保存成本，
具体权重、阈值及适用类别待标注用例验证，不能把单一 LRU/年龄阈值当成完整机制。
模型可提出摘要与候选，确定性 owner 校验版本、引用、权限、预算与保护条件后提交。

摘要先验证并可靠提交，再清理旧数据；失败不先删后补。摘要本身和它保留的 provenance
也有预算，不能层层摘要形成无限历史。原文已经删除时，明确来源已过保留期/不可回查，
不能伪造仍可恢复的引用或把派生摘要提升为已验证事实。
重要性高给予优先保留，不自动获得无限期、无限容量豁免；用户固定保留也受专门配额。
安全/授权与未决副作用的最低必要集合若无法放入预算，应停止相应新接纳并报告，
不能为腾空间遗忘其约束。用户可以通过完成/取消工作或调整预算解除压力。

### 3. 会话生命周期与归档资格

以下是待上游冻结的宿主协调生命周期示意，不直接向 pinned SessionState 增加枚举：

`受管理/可执行 -> 收敛中 -> 可归档 -> 已归档 -> 已清理`

归档资格至少要求：所有关联任务已终态；没有在途工具、待接纳输入、待投递结果、
待批准/待澄清交互、未决副作用、租约或未结算的上下文/记忆更新；必要结果已可靠记录，
并满足明确的结果交付/过期策略。清理前重新校验引用、任务 epoch 与版本，
避免检查后新输入重新引用该会话的竞态。
任务 Completed 只是必要条件之一；长期空闲的挂起任务也不等于完成。

归档释放受管理/驻留名额，保留有限元数据、有效摘要和必要工件；归档受独立数量/
字节/保留期约束，到期或容量压力下可进入清理。查询/恢复按需且消耗相同接纳预算，
不能启动时把全部归档恢复成驻留会话。终态任务不复活；后续需求可关联旧摘要创建
新工作。已清理内容明确不可用，不为了“继续”而编造细节或盲目重做副作用。

### 4. 跨存储一致性、删除与回收效果

复用 Mira 的 scope/TTL、compact/retention sweep、erase、checkpoint/ArtifactStore
能力，避免自建第二记忆库。容量驱动清理与用户隐私删除分别建模：前者失败回滚并
报告容量压力，不能冒充隐私删除完成；后者沿用 Pending hold/fail-closed，清扫不能
释放隐私 hold。隐私删除还要防止内容从摘要、归档、索引或受管备份重新进入上下文。

共享工件与记忆必须经所有权/存活引用检查，不能因清理某一会话删除其他活跃任务
或长期记忆仍依赖的证据；也不能因单条永久引用使整个历史无限保留。
跨 EventStore、Memory、checkpoint、artifact、索引的清理可中断、幂等、可恢复，
处理崩溃点和迟到写入，避免恢复后复活已删对象。
墓碑、回收日志与输入去重记录也需有限窗口；须同时定义旧输入重放的拒绝/过期语义，
不能在去重记录清理后把过期请求当成新动作重做。

容量核算区分逻辑有效载荷、可重用存储和实际文件占用，覆盖数据库/WAL/临时文件/
索引重建/备份峰值。删除行数不能作为磁盘空间已经回收的证明。

### 5. 生命周期 owner 与上游反馈

Mira 提供通用遗忘/会话归档协调、预算接纳和可观察结果；Mirage 提供部署预算配置、
存储/平台测量与产品呈现。具体 facade/可选 SPI 由上游评审，不修改 pinned 源码。
全部回收任务沿现有 ContextMemorySupervisor/kairo owner、取消与 shutdown，
每趟工作及失败重试有界，未来异步实现前需加载 pinned integration skill 的相关卡片。
诉求在 [MIRA-20261027-001](../dependency_feedback/mira.md#mira-20261027-001)
与 [mira#111](https://github.com/Linductor-alkaid/mira/issues/111) 跟踪。

## 备选方案

- 永久保留原文、只降低激活：不满足有限存储。
- 移到无限归档/远端：没有形成受管资源上界。
- 仅 TTL 或固定条数清理：无法处理写入速率/单条大小差异、重要信息与恢复依赖。
- 任意淘汰最旧会话或任务一结束即删：可能破坏待交付结果、在途更新和副作用恢复。

## 影响与风险

这是维护者授权的目标原则修订，当前产品仍运行 DEC-101 的历史实现，尚未切换默认
配置或执行任何数据清理。保留期变化及旧数据迁移必须先冻结设计，提供占用/损失预估、
可观察的迁移结果与失败恢复；不能把文档更新写成新容量约束已生效。
遗忘意味着部分细节不可恢复；需要评估关键事实/承诺保留、错误遗忘、摘要漂移与
资源收敛，不能只以删除率或压缩率验收。

## 验证方式

小配额压力测试覆盖持续输入、不同大小对象、全部受保护、归档满、磁盘满、清理失败、
共享证据、晚到结果、任务重新引用、断电/重启点、取消、拒绝、超时与 shutdown。
验证总驻留会话数、归档和实际持久化占用/峰值保持在冻结预算内；回收进展与降级
结果明确。覆盖压缩后关键约束保留、摘要源已删、重放窗口过期与隐私删除不复活。
本轮只有契约/文档核对，未执行这些行为测试；负责人 Mirage 维护者，待上游设计、
目标设备预算和原型就绪后补验，不据此标记实现完成。
