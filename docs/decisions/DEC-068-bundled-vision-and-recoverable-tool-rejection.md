# DEC-068：默认视觉运行包与工具拒绝恢复

> 状态：Accepted
> 日期：2026-10-11
> 依据：维护者要求检查两次产品会话失败，固定已验证的 Mirador / ncnn / OCR 并默认使用。
> 工作项：M7-13、M7-14

## 决策

Linux 原生产品预设默认构建 pinned Mirador PP-OCR/ncnn，并在构建阶段生成固定
PP-OCRv5 mobile 资源包。源提交、源文件和转换产物 SHA-256 固定，复用已验转换；
模型不进入 Git，不在产品运行时下载。资源与许可证随安装包交付；缺失、损坏不能静默
降级。没有持久化 vision 设置时产品自动选择包内清单；明确的自定义/空清单及 CLI
覆盖仍优先，空覆盖可恢复启动。普通开发服务保持显式启用，产品平台授权保持原规则。

只读截图允许最多 32 MiB 原始 BGRA 输入，窗口/显示默认经 Mirador resize_area 生成
最长边 1600 的预览，PNG 输出仍限 8 MiB。ROI 保持 1:1 和 8 MiB；预览元数据明确
原始范围、输出大小、两轴比例，不能生成动作引用。几何、epoch、有效期与取消门禁不变。
截图四次额度只在开始采集时消耗，参数、几何和预算拒绝不消耗采集额度。
产品 OCR 采集上限扩至 32 MiB，仍保持 5 秒期限及 128 结果上限；SoM 使用明确局部
ROI，避免大屏标记图输出超限。语义会话树预算为 4096（Provider 已有默认上限），
输出预算不变且截断显式标记；更大树或无 AT-SPI 的 UI 使用视觉路径。
AT-SPI 遍历逐节点及子节点枚举检查取消；子节点准入包含待遍历队列的节点预算，
拒绝/取消不发布部分快照，也不占用新引用注册表。
X11 标题属性在 Backend 启动时可创建 atom，读取必须有界、校验 UTF-8；经典
WM_NAME 的 XA_STRING 按 Latin-1 解码，避免先启动服务后启动 UI 时向 IPC 写入坏 UTF-8。

执行前拒绝及明确无副作用的 Provider 拒绝可由新观察后修正参数。拒绝回执不算成功。
宿主仅信任本轮自身记录的 action_id、拒绝状态、未派发及无副作用事实；未知 canonical
失败、已派发但未验证、异常和不确定副作用仍封锁后续修改。不会通过忽略 failed 字段
解除真实安全门禁。失败的只读视觉尝试可由随后成功的新视觉观察替代；最后一个动作
被拒绝时仍不能借先前激活成功而结算。模型工具说明明确引用来源、条件字段、动作后
重新观察和视觉回退。

## 验收

覆盖真实会话错误序列、高分辨率预览/坐标/预算、错误修正和不确定负例；验证固定资源
校验、默认启动、离线安装布局、显式关闭和坏包拒绝。实际业务会话与默认包验收分别
记录，不能以只读工具成功声明任意应用任务已完成。无新并发 owner，不修改依赖源码。
