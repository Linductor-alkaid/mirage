# DEC-150：工作流图编辑与独立调用

> 状态：Accepted
> 日期：2026-11-16
> 负责人：Mirage 维护者
> 关联工作项：M15-21（Completed，Linux 限定增量）
> 扩展：DEC-149；替代其中标题栏入口布局

## 决策

按维护者要求，侧栏左上角以「会话 / 工作流」切换工作空间。工作流侧栏选择资产，
主区显示真实 IR 的节点与顺序、前置条件、验证、失败回退和有界回环。节点选择后显示
可编辑检查器，保留显式保存与验证发布。运行/恢复控制保留独立视图。

参考本地 ZCode 的轨道、节点灯、参与者标签及回环层次；2026-11-16 已将干净的
`~/ZCode` 从 b95ebaff 快进至 fec97590（v3.18.2）。沿用 Mirage 字体和中性明暗配色，
以选中节点的强调色、明确连线和文字状态表达层次，不引入另一套视觉品牌。

编辑器使用 integration 的标准库投影，解析、修改和验证复用 pinned Mira IR；UI 不解析
第三方类型、不拥有执行状态机。图不宣称支持 IR 不具备的任意分支或并行。
调用复用 Mira SkillPublicationRegistry 与 WorkflowRuntime::skill_tool_registrations，
各工作流是独立资产，调用边只记录被调用工作流 ID，不建立父子所属关系。
调用在实际分派时读取目标的最新已发布版本，已开始的单次调用不因更新而重放。
原子调用的稳定工具入口通过 kairo DoubleBuffer 发布不可变的 Mira Skill handler；
Mira 继续承载实际调用 Run、取消、权限和深度资源预算。
发布前对候选调用图检查直接/间接循环，拒绝环路并保留此前可执行目标。
未发布草稿不替换调用目标。导航进入目标的当前定义，以返回路径回到调用来源。

草稿只在 UI 内编辑，失败保留草稿；保存/发布必须显式触发。节点支持原子任务参数、
前置/验证条件编辑，复用段作为独立工作流发布后可插入其他工作流。禁止把模拟图或
未发布草稿显示为可运行。调用深度使用 Mira 现有默认上限 2，不创建私有执行器。

## 验证

IR 投影与编辑往返、非法条件拒绝、直接/间接调用循环拒绝、目标更新后的实际调用、资源深度拒绝、请求修订
与断线过期保护；实际 renderer 检查明暗、常规/最小窗口和键盘/选中/错误/空态。
完整产品验收和 Windows 由 M15 原门禁继续跟踪，未实跑不得标为完成。


## 契约与范围

`workflow.save/publish` 的可选 `expected_head` 在写入前检查目录当前摘要，空字符串要求
目标尚不存在。`workflow.publish.reusable` 首次暴露工作流调用入口；已暴露目标的后续
发布均更新该入口。`workflow.atom.catalog.safe_workflow_editor=true` 确认服务具有 CAS、
动态调用和 DAG 门禁；旧服务缺省为 false，native 只读，禁止发送编辑写入。
保存/发布成功后只做一次有界目录刷新，不增加后台轮询。

稳定调用工具 `workflow.<workflow_id>` 保守声明有副作用；Mira 验证实际目标参数与权限。
只有被调用工作流实际 Completed 才返回标量 true，默认完成条件校验此回执；失败与取消
保持失败/取消，不降级到旧版本。完整目标版本由实际 Mira Run 事件记录。

M15-21 当时延续 DEC-023 的当前服务内目录，草稿同步与发布不等于跨服务重启保存；长期学习
存储仍按 DEC-147 独立持久化。目录持久化、完整候选审阅与 Windows 仍由 M15-08/09
跟踪，不由本次 Linux UI/脚本测试关闭。

实施与限定验收见 [图与调用验收](../compatibility/workflow-graph-calls-20261116.md)。完整 M15、目录持久化与未执行平台不据此关闭。
