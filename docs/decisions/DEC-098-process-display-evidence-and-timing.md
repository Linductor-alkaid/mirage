# DEC-098：过程展示、完成证据范围与阶段耗时

> 状态：Accepted
> 日期：2026-10-17
> 负责人：Mirage 维护者
> 工作项：M9-14、M9-09（证据说明增量）、M9-11（耗时增量）
> 依据：维护者本轮明确要求；扩展 DEC-049/056/093，不改变动作授权与成功门禁

## 决策

思考展示继续共用 8KiB。单段长思考保留 UTF-8 安全的首尾摘要，最大 4KiB；
新段需要空间时将最早的思考正文替换为明确的展示省略提示，保留近期内容。
96 段耗尽时先淘汰最早的思考，再淘汰已结算旧活动；不得淘汰正在执行的工具。
`omitted_for_display_budget` 是可选展示字段，`truncated` 沿用投影裁剪语义；
旧历史的空截断段也显示明确原因。展示投影不回填模型历史。

动作回执增加可解释的证据范围；新帧、文本存在、进程存在、焦点身份分别说明，
不把局部 `verified` 当任意任务完成。模型按用户目标选择能证明结果的证据；
已满足的局部条件不要求额外重复 verify。焦点不可查询时，OCR 文本不能替代焦点
身份，报告证据限制，不用相同截图无限补证。最终只读收尾重验保留。

过程快照增加可选 `timings`，包含 inference/capture/ocr/settlement 四组完成次数和
累计单调时钟毫秒数。缺失表示旧版本未计量，不能伪装为零耗时。失败和取消同样
计入已经进入的阶段。推理计公开 provider 调用（含该调用内传输等待）；取帧计实际
平台采集调用（含获取首帧的等待）；OCR 计现有识别适配器调用；收尾计最终只读
核验。收尾内部可能包含取帧/OCR，因此各项不可简单相加为总时间。

指标沿现有过程事件、历史与持久化传播，不新建线程、任务监控系统或原始内容日志。
全部采样在既有 Executor 管理的串行调用路径内完成；依赖的 trace/执行监控继续
是调度与失败事实源，产品阶段耗时仅说明本层职责边界内的等待。

## 验证

覆盖长思考后新段可读、段数耗尽、UTF-8、省略原因往返、旧历史兼容；验证证据
范围与提示不会把新帧当焦点；用有界延迟 fixture 验证阶段次数、累计耗时、失败/
取消与持久化/IPC/native 展示。Linux 验证不扩展为 Windows 或实机性能承诺。
