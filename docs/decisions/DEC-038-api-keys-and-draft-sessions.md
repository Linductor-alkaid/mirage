# DEC-038：直接 API Key 与草稿会话生命周期

> 状态：Accepted
> 日期：2026-10-05
> 依据：维护者要求直接输入 API Key、空草稿不进入历史、历史可删除，参考 ZCode。
> 工作项：M6-09（Linux 首步）
> 补充：DEC-027 / DEC-037 的凭据交互；不改变 SecretRef 传输边界。

## 决策与边界

1. 模型页使用默认遮蔽、可切换显示的 API Key 输入。已保存密钥不回传 UI，只投影
   已配置状态；留空保持，显式移除才清除。model.set 增加可选 write-only api_key，
   限 2048 个可打印 ASCII 字节。普通设置只保存稳定 credential_ref，密钥存系统
   Secret Service / Windows Credential Manager；不可用或锁定时明确失败，不退回明文。
   旧环境变量配置保留兼容读取，界面不再要求输入变量名。
2. 平台凭据 API 仅在 Platform Backend；Runtime 注入读/写回调，integration 用 Mira
   ISecretResolver 解析 SecretRef。Linux 有界 GDBus 调用不订阅/派生事件线程；模型保存
   在现有 Executor 管理的串行 handler 内，传输读取在 Mira transport blocking worker
   内执行。D-Bus 方法共用 2 秒预算，连接/认证套接字设置 2 秒超时，成功/失败对调用方可见。
3. 更新密钥采用新引用，配置原子保存成功才启用新引用；配置失败时移除新凭据，旧引用
   保持可用，清理失败明确报告。删除/移除旧引用在配置成功后执行，失败仍可诊断。
4. 新建是 UI 草稿，未发送不打开远端会话、不进入历史列表；反复新建复用已有空白草稿。
   首发冻结文字/权限/推理，open ACK 后发送。接纳或历史/事件出现实际消息后进入列表。
   重连加载历史不把主会话或空远端会话当作新草稿，失败保留草稿且可重试。
5. 历史行提供删除和确认，确认显示首条输入与最近消息摘要识别目标；运行/提交中的会话必须先停止，删除在服务 ACK 后移除本地。
   产品 session.delete 复用 Mira close 删除普通会话；历史遗留的主会话只清除产品对话
   记录，保留任务默认绑定设备身份。删除后的记录不再持久化，迟到事件不能重建本地行；重连按服务端列表及空历史清理已不存在的稳定记录，保留草稿/活动请求。
   主会话若有活动任务同样拒绝；不将历史删除误作关闭 Runtime Service。

## 验收

配置/IPC write-only 与旧请求兼容、密钥上限/配置失败/清理失败、真实系统凭据保存读取
移除与重启引用恢复；草稿重复新建、首发/失败/迟到 ACK、空历史过滤、选择/删除后回退、
活动拒绝与服务重启不复活。Debug/Release、ASAN/UBSAN/TSAN；正常/最小明暗窗口和
API Key 遮蔽/显示、历史删除确认截图。真实密钥不出现在截图、日志、提交或返回模型 JSON。
Windows 凭据与 IME 保持目标环境补验，不由 Linux 冒充。
