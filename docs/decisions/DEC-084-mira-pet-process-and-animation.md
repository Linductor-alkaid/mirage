# DEC-084：mira_pet 独立状态窗口与分段动画

> 状态：Proposed
> 日期：2026-10-12
> 负责人：Mirage 维护者
> 冻结里程碑：M8-01（状态/进程契约）、M8-02（素材/播放契约）、M8-04（平台默认值）
> 替代/被替代：无；扩展 DEC-045 的产品子进程拓扑，保留其 Runtime owner
> 需求依据：维护者要求新增独立进程 `mira_pet`，在主窗口被遮挡或进入后台时持续展示 Mira 状态，并按每个动作单独截取循环阶段。

## 背景与问题

主窗口在 Agent 操作其他应用时常被遮挡、最小化或关闭，用户无法持续获知任务进度。
现有托盘 tooltip 和目标高亮 Overlay 不能完整承载角色动画与当前执行阶段。
新增窗口必须跟随实际 Runtime 状态，且不能干扰正在进行的桌面输入或成为视觉目标。

当前用户提供的 H3 v5 素材含九种动画：looking、typing 与调整后的 enter/exit
均已确认使用。v2/v3 库存与当轮缺素材记录保留于 M8 历史。
运行状态源文件整体包含动作进入、持续和回落过程，
即使容器设置无限循环，也不能据此认定全片适合在运行阶段反复播放。

## 决策

以下独立进程及分段循环目标来自明确需求；具体契约和默认值为提案，按关联工作项取证冻结。

1. 新增 C++20 产品可执行文件 `mira_pet`，建议放置于 `apps/pet/`。由托盘内嵌的
   Runtime Service 持有子进程身份、启动/回收句柄和故障结果，与 `mirage-native` 同级。
   主窗口关闭不退出桌宠；桌宠关闭或渲染故障不取消 Agent。桌宠不初始化第二份 Mira。
2. 桌宠仅经现有 Local IPC 消费状态。服务端从 Mira/Task/Workflow、真实工具执行缝和
   Desktop Action 状态投影产品显示状态；不新建任务状态机、推理循环或独立任务监控。
   提议增加只读 `pet.status` 快照与 `pet.updated` 通知，沿用 v1 加法扩展、能力探测、
   Topic 广播和溢出恢复纪律。wire schema 与 golden vectors 在 M8-01 同步落地。
3. 显示启动、待机、思考、看、鼠标、键入、任务成功、任务失败、退出，另用状态文字明确
   等待确认、暂停、取消、人工接管、断连和未知阶段。成功来自宿主已核验终态；可恢复的
   单个工具失败不等同于整个任务失败。没有真实阶段证据时显示“执行中”。
4. 运行状态动画分别记录 `intro`、`loop`、`outro` 帧区间及原始时长。进入动作可播放
   一次 intro；状态持续期间只重复 loop，转换可以有界打断。当前 v5 enter/exit 按
   素材声明设为 `once`，即使 WebP 容器 loop=0 也禁止重复；启动未 ready 时改用明确
   文字/静态持有，正常退出按 owner 收尾期限播放或打断。紧急停止、取消和故障不得等待动画
   播完。源动作确认不等于分段播放及目标平台运行验收。
5. 暂定复用已授权 pinned EUI-NEO 的本地渲染与窗口公开能力，不调用其 async/network/
   audio。公开接口提供透明 framebuffer、无边框和 always-on-top 请求；这些请求必须
   在目标窗口管理器实测。当前 Linux 预览用 libwebpdemux 有界解码当前状态的 WebP，
   由 Mirage 播放器按 manifest 选择 RGBA 帧，EUI ImageStream 只接收选中帧；最终
   安装资源布局与 CPU/GPU 预算由 M8-02/03 验收冻结。不修改 pinned 依赖，
   不额外引入浏览器壳。
6. 每个进程只设一个 Executor owner。托盘复用 Runtime Service owner；桌宠采用
   DEC-033 原生 UI 的进程 owner 边界，管理 IPC blocking worker、有限资源加载、
   取消和动画唤醒。数据跨上下文使用 kairo 的 Topic / LatestMailbox / MpscChannel；
   UI 主线程持有播放状态和 GPU 资源，平台 SDK 回调只校验/投递。平台窗口属性、
   输入穿透、子进程和屏幕映射位于 Platform Backend/Adapter 边界。
7. 暂定产品入口自动开启桌宠，提供独立启停/恢复设置；普通显示尺寸约 200 逻辑像素，
   初始在可用工作区边缘，默认不主动取焦。实际可点区域与透明区域须分离，Agent 输入
   目标和截图范围与桌宠重叠时先避让并重观察，不能把桌宠当成目标或忽略真实遮挡。
8. 先交付 Linux X11 预览；XWayland、原生 Wayland 和 Windows 分别验收。平台不能
   实现所需透明/置顶/穿透语义时明确诊断并保留未完成门禁。全屏、系统安全桌面等场景
   按实测记录能力边界，不宣称对全部系统表面无条件置顶。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 主窗口内动画或只更新托盘 | 主窗口遮挡时仍不可见，托盘不足以展示连续动作 |
| 扩展现有服务内 Overlay 播放角色 | 可复用部分窗口能力，但不满足独立进程需求，也耦合目标提示与角色生命周期 |
| 桌宠直接连接模型/Provider | 重复 Runtime，不能准确反映当前 Agent 的动作和终态 |
| WebP 整文件自动循环 | 无法分别控制进入、持续、退出，且原生可控动画解码尚未核实 |
| 新增 Electron/CEF 壳或第三方动画调度器 | 增加依赖与运行成本；优先验证既有 UI 与 Executor 能力 |

## 影响与风险

- 扩展产品拓扑、只读 IPC、外观偏好和安装载荷；旧客户端通过能力位保持兼容。
- 源素材在用户下载目录，不能成为发布时绝对路径依赖；导入需来源、摘要、许可和受控
  工件清单，较大素材不直接进入普通 Git。v5 九态需分别裁切及视觉验收，
  启动/退出需确认 once 和期限打断。
- 桌宠覆盖目标、焦点抢占、动画污染截图、多个任务争抢显示及断连后陈旧状态是强制门禁。
- 当前阶段与运行动作的精确循环区间尚未冻结；README 的“无缝循环”声明不作为验收证据。
- 桌宠启用失败必须可观察，不能导致正在运行的任务丢失，也不能静默反复拉起子进程。

## 验证方式

状态 reducer/快照恢复、IPC golden/fuzz、分段时钟和竞态、进程故障注入及目标平台的
置顶/透明/穿透/避让测试，见 [M8 测试矩阵](../plans/m8-mira-pet.md)。循环状态保留
逐帧区间、接缝预览及多轮播放记录；enter/exit 保留单次播放与打断证据。Linux/Windows
门禁独立保留，未运行项不标完成。
