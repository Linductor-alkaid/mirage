# 会话稳定分段与活动预览隔离（M6-52）

> 日期：2026-10-23
> 负责人：Mirage 维护者
> 状态：Completed（Linux 本轮实现/配对验证）；目标平台门禁开放
> 基线：c7ecd88 / EUI 19acab6；依据 DEC-108

## 问题与边界

不同 LocalMessage 本来逐条构建 Markdown，未将整个会话拼为一个段落。Mira
已交付的过程投影还用独立 Part ID 保存先前完成的 text/thinking/tool；最新
流式预览单独位于 message.text。公开 conversation::Part/预算和 ChatModel
apply_process/apply_preview 已足以表达此边界，无需修改协议或重复实现解析器。

原 ConversationLayout 在同一消息任意字段变化时清空全部宽度几何，所以预览
追加会重新测量全部已完成过程段，timings/tool 更新也会重测未变正文。
render_process 即便 text 过程段完全离屏仍调用 Markdown.viewport，后者在裁剪
前须查找/建立全文布局计划。段数超过其 8 项计划缓存时，会反复淘汰旧计划。

本轮按现有可信分段保留几何：每条消息的两个精确宽度槽分别记录正文、失败
文本和按 Part ID 对齐的过程段有效位。正文变化仅失效正文；过程追加/替换/
删除/重排和展开状态按精确 Part 内容与 ID 匹配保留未变高度；只重算当前行的
合计/位置。连续多次 prepare 而未 measure 时失效标志累积，不复活旧缓存。
旧合计标为不可用，绝不能用于 M6-51 的溢出证明。字体/缩放清空所有宽度，
新宽度、换会话和 8 MiB 源预算回退保持完整计算。有效位和高度向量受既有
80 消息/每消息两宽度/过程预算约束，计账增加保守布尔预算，没有第二份文本缓存。

完全离屏的 text 过程段保留既有高度推进位置，不进入 Markdown build/布局；
进入视口（含原有 64 逻辑单位 overscan）时重新构建可见树。可见段落继续消费
EUI 的公开解析/布局/viewport，未另造 parser、线程、队列或定时器。

不按空行把同一份 Markdown 强行截为“永久稳定”前缀。未闭合 fenced code、
列表续写、引用式链接定义等可能让后续输入改变前文解释；这些仍交给 EUI
完整语义和既有块缓存。单个活动 Markdown 长段仍需重排，不能宣称本轮解决
了所有长文卡顿。历史若确实被修订也会按精确内容失效，不仅看 complete 状态。

## 验证方法

缓存回归以布局调用计数验证：活动正文更新不调用稳定 Part 的测量，过程追加/
展开/重排只测量相应 ID，timings/终态变化不重测未变正文；两次未测量的源变化
不会误用中间状态。另验真实滚动、终态头位置、旧过程段离屏/重新进入和清空
缓存后的精确全高，延续原 UTF-8 选区、主题/DPI/窗口与过程展开测试。

新增 --settled-parts 基准构造 16 个独立已完成 text 片段（每片段 <=960 B）及
16 个已完成工具片段，总 text 14,850 B（单片 921/940 B），在协议 16 KiB 预算内；逐次断言 valid_parts、
实际接纳的 parts 和 preview。默认活动正文很短，加 --long-visible 则活动正文
15,984 B；配合 --long-history 还有 40 轮不同历史和折叠思考。输入全部合成，
不读取真实会话，不调用模型。前后同一新基准源码、Release flags、字体目录和
EUI 静态库；基线保存旧 app.cpp 和 conversation_layout.hpp 独立编译。

每 case 5 预热/60 采样，三轮 AB/BA/AB，Xvfb/llvmpipe，LP_NUM_THREADS=2。
原始二进制、argv、逐轮阶段统计/CPU/RSS/负载与截图位于
out/frontend-segments-20261023/。不把不同负载、不同轮次百分位拼接；不以
软件渲染推断 Windows、硬件 GPU、真实 compositor 或物理高 DPI 的帧时。
未验目标平台由 Mirage 维护者取得环境后同字体/输入补跑。

## 三轮配对结果

取前/后各三轮 p50/p95 的中位数，单位 ms。48 B 或 15,984 B 为基准
固定预览前缀，每次还追加递增编号；每次断言产品接纳的完整文本一致。
先连续三次五秒 CPU idle >75%、cc1plus/ld=0 后采样；实际 idle 为
96.43/96.14/97.73%，采样每次前后编译数均 0，期间不运行本轮其他测试/构建。
二进制 SHA、负载、argv、逐轮统计和 CPU/RSS 已保存在 quiet-* 原始记录。

| 场景 | 前 p50 / p95 | 后 p50 / p95 |
| --- | ---: | ---: |
| 14,850 B 稳定过程 + 短活动预览 | 36.70 / 38.18 | 8.39 / 9.96 |
| 同上 + 15,984 B 活动预览 | 73.14 / 74.65 | 27.89 / 46.33 |
| 对照：无多段过程的 15,984 B 活动预览 | 44.92 / 47.13 | 44.42 / 47.00 |
| 常规输入：0 轮历史 / 64 B 草稿 | 4.54 / 6.39 | 4.24 / 6.20 |
| 常规输入：0 轮历史 / 4096 B 草稿 | 5.34 / 7.37 | 4.86 / 5.44 |
| 常规输入：0 轮历史 / 16000 B 草稿 | 5.09 / 7.61 | 4.70 / 5.05 |
| 常规输入：40 轮历史 / 64 B 草稿 | 6.15 / 11.62 | 5.92 / 7.63 |

稳定过程 + 短预览的 p95 降 73.9%；进程 CPU 总时间中位 5.08→2.07s，
RSS 174512→174252 KiB。稳定过程 + 长预览 p95 降 37.9%，进程 CPU
8.62→4.18s；RSS 179120→183608 KiB，增加约 4.4 MiB，不能宣称内存改善。
进程 CPU/RSS 包含初始化、预热及后续 stream_total，不等于单帧值。

三轮稳定短预览 p95：前 73.58/37.78/38.18，后 10.94/9.96/8.84；
稳定长预览 p95：前 58.21/74.65/75.01，后 66.84/42.84/46.33。
长预览首对尾延迟反而升高，保留该波动，不以跨轮拼接或最佳值替代中位数。
无多段过程的长预览对照 47.13→47.00ms，基本持平；常规 40 轮 / 4096 B
输入 p95 6.72→8.03ms，未普遍加速。本轮针对大量稳定过程的重复工作，
不把对照波动解释为其他路径的收益。单一活动长 Markdown 仍超过 16.7ms 帧预算。

后续 stream_total 也原样记录在 quiet-summary.json；它们在上一个合成场景
之后运行，不与独立短预览数据混用。性能结论只适用于本轮同机软件渲染输入。
