# 长历史滚动条溢出探测优化（M6-51）

> 日期：2026-10-23
> 负责人：Mirage 维护者
> 状态：Completed（Linux 本轮实现/配对验证）；目标平台门禁开放
> 依据：DEC-108；维护者要求继续优化前端

## 开销与实现

基线为本地 625a335 / EUI 19acab6。前轮有效 15,984 B 变化段落已从原始
产品 p95 409.20 降至 62.38 ms，但每次变化仍经过两个宽度的高度计算。
核对 pinned 公共 `components/scrollview.h`：ScrollView 第一次在完整宽度
测量，仅用结果判断是否需要滚动条；一旦溢出，再按减去 12 单位 gutter 的
实际宽度测量，后者才是最终 contentHeight / scrollMaxOffset 的来源。

Mirage 保持这个组件和最终真实测量。ConversationLayout.prepare 已按精确源
内容/字体/缩放失效缓存，并移除退出当前会话的行。未变化行在完整宽度下的已知
高度，加上所有行间距，是本轮完整宽度总高度的下界：未知行实际高度非负。
只有下界严格超过视口且留出 1 个逻辑单位的舍入余量，才让初次测量回调输出
一个 height+1 的非交互占位，证明溢出并进入实际 gutter 宽度的精确测量。
这避免为变化长文计算不会用于最终滚动范围的完整宽度排版。

真实树（ScrollView root 已存在）永远走原内容路径；非完整宽度的测量也走原路径。
首次打开、窗口新宽度、字体/缩放失效、源变化或单会话/预算回退使下界
不足，以及接近溢出边界时均完整测量。消息很多时，单靠固定行间距已能
证明溢出，因此即使冷打开或字体缓存失效也可安全省去首轮。保留原 contentKey、滚动条出现规则、最终内容宽度、
全高、跟随/手动浏览、选区与 UTF-8 文本；不固定 gutter，不裁短或丢弃预览。

此优化位于 Mirage UI callback 边界，不改 pinned EUI，也不引入新布局引擎、
线程、队列或定时器。EUI 已有 ScrollView/scrollState 足以承载本轮需求。
依赖升级必须复验“初次高度仅用于溢出判定、最终范围取实际宽度”这个消费前提；
若上游改变此行为，应去掉此优化或改用其新的公开测量入口。它不是通用 contentHeight
API，也不能把下界当作最终高度。仍遍历至多 80 条消息并保留离屏轻量占位。

## 验证方法

同机 Release、1180×800、私有 Xvfb/llvmpipe，产品 Noto Sans SC CFF 字体目录，
LP_NUM_THREADS=2。前后二进制使用相同基准源码和输入，基线在修改前复制；
每 case 五次预热、六十次采样，按 AB/BA/AB 三轮，取各轮 p50/p95 的中位数。
长段正文 15,984 B，逐帧断言在 16 KiB 内且 ChatModel 接纳文本完全一致。
保留长/短历史、多段/无换行输入和短预览；最终样本不与本轮构建/测试并行，宿主其他工作另记。

缓存回归覆盖无已知行、等高/舍入边界、未知/变化行、精确宽度、重排、删除、
字体/缩放、换会话和 8 MiB 超预算回退。实际会话改变长历史末条后，将优化后的
scrollMaxOffset/正文位置和高度与清空缓存后的完整测量比较，并复验跟随状态。
原窗口/DPI/主题、过程展开、手动浏览、滚动中部选区回归继续运行。

原始证据保存在 out/frontend-overflow-20261023/。不调用模型，不读取真实会话
或账号配置，不重启正在运行的前端。Windows/真实 compositor/硬件 GPU/物理
高 DPI 未执行，负责人 Mirage 维护者，取得目标环境后按同字体/输入补跑。
不能用本轮软件渲染数据保证任意设备或变化文档达到 60 FPS。

## 固定 P core 的 CPU 诊断（辅助证据）

采样开始时另一工程编译已退出：六次进程前后 compiler_count 均为 0；
此前一分钟 loadavg 较高但持续回落，不能据旧 loadavg 宣称仍有并行编译。
这批绑定 CPU 0/1 的数据独立报告，不能与此前不限亲和性的 62.38 ms 混算。

| 固定亲和性负载 | 基线 p50 / p95 ms | 优化 p50 / p95 ms |
| --- | --- | --- |
| 15,984 B 变化长段 | 63.94 / 65.28 | 46.36 / 48.36 |
| 随后的短预览 | 12.13 / 13.18 | 12.22 / 14.76 |

整个进程（含启动、预热、两段 65 次更新、退出）的 user+system CPU 时间

短预览 p95 13.18→14.76 ms，未证明同样加速；不把主负载收益外推所有交互。
RSS 182752→182088 KiB，微小差异不作内存优化保证。

编译退出后重新应用空闲门槛，再测不限制 CPU 亲和性的完整五 profile。
两组实验配置不同，分别保留，不拼接百分比。

五个 profile 均按 AB/BA/AB 三轮；全部 30 次进程的前后 compiler_count 均为 0。
