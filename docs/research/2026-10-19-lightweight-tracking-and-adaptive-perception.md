## 结论与需求边界

维护者允许在模型理解、OCR/YOLO/Tracker 可用的条件下尽量降低分辨率与画面质量。
应优化采集至推理的总成本，并按消费能力选择最低可用画质；不要求整屏常驻原始
分辨率，也不将 pet 素材清晰度与机器感知画质绑定。方案已补入 DEC-109 与 M9。

小型无人机的视觉能力常见三类：无深度网络的局部匹配、轻量单目标深度跟踪、
为特定任务训练的小网络。它们以减少任务范围、输入像素、搜索区域、重复计算和
张量精度换取资源收益；不能据设备外形推断视觉运行在普通飞控 MCU。
[PX4 官方说明](https://docs.px4.io/main/en/companion_computer/)区分飞控与机载伴随计算机；
PULP-Frontnet 则使用 Crazyflie 配 AI-deck/GAP8 专用视觉计算。

## 公开实现与机制

以下链接于 2026-10-19 回读。性能数字只说明原作者的指定实现，不是 Mirage 指标。

| 实现与原始资料 | 轻量化机制 | 对 Mirage 的启发和限制 |
| --- | --- | --- |
| [OpenMV 模板匹配](https://docs.openmv.io/dev/openmvcam/tutorial/image/matching/template-and-similarity.html) | 灰度 NCC、小模板、搜索 ROI；diamond search 先粗后细，exhaustive search 可调步长 | 固定外观控件适用局部验证；缩放/旋转/相似模板会歧义，粗搜索可能漏峰。不是任意类别检测器 |
| [MOSSE 原论文](https://www.cs.colostate.edu/~draper/papers/bolme_cvpr10.pdf)及 [OpenCV 实现](https://github.com/opencv/opencv_contrib/blob/4.x/modules/tracking/src/mosseTracker.cpp) | 目标邻域灰度预处理，FFT 相关滤波复用滤波器，响应峰/PSR 判丢失，递增更新 | 无需大模型权重，但浮点工作区仍占内存；漂移、相似控件和目标替换须额外身份核验。FFT 不是现有 Mirador NCC 的算法描述 |
| [NanoTrack 作者实现](https://github.com/HonglinChu/NanoTrack) | MobileNetV3 轻量 Siamese 网络，目标模板特征复用，仅处理局部搜索 crop，ncnn 部署；README 列模型约 2.2 MB | 与 pinned Mirador 已有 NanoTrack 后端契约直接相关；单目标初始化后跟踪不提供整屏 OCR/语义。权重文件大小不等于运行 RSS，多目标开销需逐目标计量 |
| [PULP-Frontnet 作者实现](https://github.com/idsia-robotics/pulp-frontnet)及 [原论文](https://arxiv.org/abs/2103.10873) | 人体相对位姿专用网络，160×96/80×48 输入与通道数变体；8-bit 量化、整数推理、GAP8 部署，NEMO 导出并面向 DORY 生成代码 | 确有微型无人机人体跟随实验；借鉴任务专用与定点化方法，不移植人体网络识别桌面文字。仓库 DORY 部分步骤仍标 coming soon，完整应用另链 NanoCockpit，不能宣称直接一键复现 |

以首帧框选/检测初始化的跟踪器，后续主要回答同一对象移动到哪里；检测器负责
新对象和重捕获，OCR 提供文字，模型/平台语义负责目标含义。成功跟随一个大目标
不能证明密集桌面里几十个相似按钮的身份都正确。缩小搜索窗节省工作，但跳帧或
快速滚动会把目标移出窗口，必须配合运动补偿、搜索预算与失败重捕获。

## Mirage 已有能力与实际成本

已核对公开头、NanoTrack 模型契约与 supply-chain 记录，没有引入 OpenMV/OpenCV
或另一套 Tracker 运行时：

- `ObjectTracker` 提供有界池、NCC/PSR、多模板、运动/语义及重捕获原语。公开默认
  `template_thumb_side=32`，池预算 1 MiB；该预算不是源帧/临时工作区/进程 RSS。
  `verify_track` 在验证 ROI 内逐整数偏移形成响应；模板小不代表大范围搜索便宜。
- `integrations/tracker_nanotrack/nanotrack_backend.hpp` 已提供可选参考后端，默认
  127×127 exemplar、255×255 search。initialize 缓存模板特征，update 跑局部搜索
  分支与 head。模型契约固定，输入 RGB、当前单线程确定性约束不能擅自改变。
  16 MiB work budget 不单独计量 ncnn 所有内部中间张量，仍需测 RSS。
- [Mirador 合成跟踪基准](../../third_party/mirador/docs/benchmarks/linux-x64-object-tracking-2026-09.md)
  已证明变化门控、运动补偿与语义通道在其合成场景中的作用；不冒充真实桌面质量。
  [Mirage 实测记录](../compatibility/mirador-tuning-and-capabilities-20261016.md)
  中 NCC/PSR 需校准；NanoTrack 没有本轮已登记的真实权重验收，M9-08 仍开放。
- 当前 `DesktopImageTurn::preview_downscale` 先取得像素，再按最长边 1600 缩放并
  复制输出；能减少后续图像量，不代表采集端已经少读/少复制像素。后续应优先
  探测平台源缩放/ROI/可共享帧；只提供整帧的 backend 要报告实际成本。

## 自适应分辨率与质量方案

将源证据、工作表示与模型输入分开。派生图均记录源帧、水位、原点、有效矩形、
比例/方向与 representation revision，复用 Mirador 变换/裁剪/缩放 API，不自建
视觉算法。先裁 ROI 再缩放；不同消费者不各自生成整套金字塔。

| 消费用途 | 候选表示与策略 | 不能假定的保证 |
| --- | --- | --- |
| 全屏外围变化巡检 | 比较最长边 640/960 等低分辨率表示、紧凑灰度签名；按权限/需求限频 | 小字、颜色变化或瞬态可能漏检，低清无变化不授权动作 |
| 模型页面概览 | 比较 640/960/1280 长边，保留任务所需颜色和布局；有文本观察时不重复送图 | 长边数字不是跨设备统一最低画质，微小图标/图表可能需要 ROI |
| OCR/小图标检测 | 从新鲜源帧取得目标 ROI，选择足以识别的最小尺度；必要时局部原生像素 | 放大已丢失笔画的低清图无法恢复信息；置信度高也不证明文本正确 |
| 跟踪 | 少量任务相关目标、有限局部搜索窗；NCC 灰度模板或符合既有契约的 NanoTrack RGB crop | 不每帧跟踪所有 OCR 框；不修改固定模型张量尺寸来假装省算力 |
| 动作重验/后条件 | 当前目标/路径/接收端的必要清晰 ROI，源帧/权限检查保持 | 全屏低清、预测框和缓存不能替代局部证据 |

这些尺寸是待测档位，不是冻结默认值；M9-07 在实现前登记候选档位与准入/质量
阈值。选择按 OCR 关键字段正确率、YOLO 小目标召回/定位、Tracker ID 交换/漂移、
模型 grounding/任务完成及输入错误率共同验证。按未达标、歧义、小特征或证据
过期触发局部提清晰度；稳定后按迟滞降低，避免每帧升降档。全图按需升级仍保留。

JPEG/WebP 等有损编码仅在模型传输契约支持且通过质量对照后考虑；现行 PNG 不
在本轮更改。本地感知保持有界原始像素/签名/特征，避免先压缩再解码。压缩文件
小不等于解码后内存小；PNG 更高压缩级别也不自动降低 CPU。灰度只用于支持它的
路径，不把现有 RGB YOLO/NanoTrack 或依赖颜色的任务直接换成灰度输入。

| 紧密像素表示 | 单份容量（算术） |
| --- | --- |
| 3840×2160 BGRA8 | 31.64 MiB |
| 1280×720 RGB8 | 2.64 MiB |
| 960×540 Gray8 | 0.49 MiB |
| 640×360 Gray8 | 0.22 MiB |

表中不是同等语义质量或端到端 RSS 对比。源帧、模型权重、推理张量、派生缓存和
GPU 暂存仍计总预算；平台无源缩放时，低清派生无法免去全尺寸取帧成本。候选
profile 的 cache key 须含预处理/尺度/格式与模型身份；表示切换重建比较基线和
相应跟踪模板/坐标映射，不能用错误尺度续接或把重采样差异当作任务状态变化。
仅有表示改变不撤销仍有依据的语义绑定，执行引用继续检查当前版本及权限。

## 建议实施与验收

1. M9-06/07 先接通有界共享帧、低清巡检/概览与按需清晰 ROI；统计源侧实际取帧/
   拷贝字节，不能只统计 PNG 大小或输出分辨率。
2. M9-08 优先消费已有 NCC/PSR/运动补偿，严格控制目标数与搜索窗；仅对仍需要
   深度跟踪的对象评估 NanoTrack。MOSSE/LightTrack 不成为新的直接依赖，若现有
   公开能力实测不足再按依赖反馈流程讨论算法优化。
3. M9-11/12 对同一任务/真实桌面/模型作档位扫描，覆盖小字、密集代码、相似图标、
   细边框、颜色状态、滚动、遮挡/pet、源/表示切换及慢消费者；分别报告识别/ID/
   动作/模型理解与 CPU、RSS、GPU、复制量、帧年龄、P50/P95、实际 backend 调用。

完整阈值、样本集、设备与权重由 Mirage 维护者在基准前冻结；以满足质量门槛的
CPU/内存候选构成取舍，不要求单一档位同时最优。本轮未下载权重、编译外部项目
或运行性能/识别基准。补跑条件：共享帧/ROI 接线、授权实机桌面、指定模型权重与
可重置任务集到位；现有 M9 完成状态不因本调研改变。
