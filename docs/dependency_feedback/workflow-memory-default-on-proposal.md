# 默认学习与长期存储：最小依赖补齐方案

> 状态：Accepted（维护者已授权补齐 Mira 并升级 pin；元数据首增量已实施，验收见 M15-17）
> 日期：2026-11-14；负责人：Mira/Mirage 维护者
> 来源：用户要求默认开启学习，推进长期存储与在线验收
> 工作项：M15-17；缺口：MIRA-20261112-001

## 产品结果

Runtime Service 默认开启 Workflow 学习，用户可明确关闭；由进程唯一 Executor 上的
共享 Memory owner 承载，启动恢复、工作中接纳、关闭和失败均可观察。初期只记录 Mira
规范化的 Episode/Lesson 元数据，不把默认开启等同于默认录屏或保存截图。视觉工件仍
须经过既有捕获授权、分类、总量预留和来源事件核验。

## 需要 Mira 补齐的最小能力

不要求 Mirage 实现完整 M31，也不在 Mirage 私建配额库。建议在 Mira 存储边界冻结：

1. 配置持久总字节硬限额、元数据/恢复预留、单次操作与在途限额；明确数据库/WAL/
   sidecar/工件的计量归属，区分逻辑数据量、可复用空间与目录实际占用/峰值。
2. 实际提交前有界接纳；满容量时返回明确结果，不能只靠每条记录/工件正文限额。
   失败不得无限重试，也不能以清除用户现有记录掩盖容量不足。
3. 重启可恢复的操作身份/部分提交回执，以及限量盘点/续扫水位；未完成操作不伪造回滚，
   共享引用安全与隐私删除结果单独结算。先覆盖单一 SQLite 元数据 owner，工件分层交付。
4. 相同外部 Executor 上的有限维护能力；宿主停止生产、排空、关闭 Store，最后关闭
   Executor，不新增线程或第二套任务监控。公开 API/测试/设计同步后再升级 Mirage pin。

具体类型名与实现由 Mira 冻结；上述是可验收需求，不冒充当前已存在的公开接口。
同时应核对 MIRA-20261112-002/003 的恢复异常与尝试回执，避免在线自动恢复承接已知缺陷。

## Mirage 接线与验收顺序

1. 增加默认 true 的产品学习配置与明确关闭路径；可用存储能力安装前不宣称已启用，
   启动失败/降级状态明确报告，不悄悄换临时目录或丢弃已有数据库。
2. Runtime Service 持有长期 Store owner，默认使用产品 state 目录中的专用子目录；
   禁止将用户目录或既有运行目录用作测试库。所有启动失败路径同样关闭 Store 后再关
   Executor；正常关闭确认 Host/Workflow 的最后写入完成。
3. 冻结跨会话召回授权与作用域：当前 primary Session scope 的历史持久记录可审计，
   不能仅因重启而全局检索旧 Session，也不能偷偷改成 Agent/User scope。
4. 在线验收使用当前已配置模型、隔离任务/状态目录与受控文件提供者；先验证真实模型
   给出结构化修复、实际动作完成、显式 Lesson，再验证后续同签名召回。最终场景最多 2 次模型
   恢复调用；诊断与最终累计 6 次尝试（4 失败、2 成功），实际入口期限 30s、输出
   2048 token，见 DEC-146 与脱敏验收记录。实际 token、耗时、成功/拒绝与存储结果分别记录，无凭据、
   用户文件正文或原始模型输出进入报告。目标平台真实桌面验收另列。
5. 补跑四配置生命周期回归、容量压力/满额拒绝、重开、部分写入/磁盘故障/擦除矩阵，
   结果达标后完成默认启用，不能以普通模型聊天成功代替恢复/学习链路验收。
