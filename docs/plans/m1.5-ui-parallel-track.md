# M1.5：UI 并行轨道与 IPC 事件订阅

> 状态：Planned
> 负责人：Mirage 维护者
> 所属计划：[Mirage 实施总计划](mirage-implementation-plan.md)
> 前置：M1（已完成，退出条件复核 5/5 通过）
> 建议发布点：无独立 tag（能力增量随 master 开发线交付；产品化 UI 与分发仍属 M5）
> 更新日期：2026-09-16

## 目标

让产品 UI（`ui/`，Web 技术栈，见 [DEC-006](../decisions/DEC-006-ui-web-frontend-packaging.md)）
与 runtime 核心并行开发：以 Local IPC 契约为唯一耦合面，前端在浏览器中（mock 数据或经
dev bridge 连接真实 Service）直观验证 M1 已交付的任务能力，用于尽早判断产品形态是否
符合需求；同时把总计划 `EXEC-02` 的事件推送面落成 wire 契约
（[DEC-012](../decisions/DEC-012-ipc-event-subscription-and-wire-schema.md)）。

## 范围与非目标

范围：

- 协议 v1 wire schema 事实源文档与 TypeScript 镜像（含 golden vectors 双端一致性测试）。
- 协议 v1 事件订阅扩展（`events.subscribe` / `event` 信封 / M1.5 事件集）与 service 侧
  `executor::comm` 承载。
- 开发期 dev bridge（socket ↔ WebSocket 转发工具）。
- `ui/workspace`、`ui/tasks`、`ui/execution` 的浏览器形态前端（mock 与真实双传输）。
- CI 接线（前端一致性测试与构建不破坏既有预设矩阵）。

非目标：

- CEF 壳选型、PoC 与窗口集成（M3，DEC-006 决策 3）。
- Overlay、权限确认流 UI、Workflow 编排视图的产品化（M5，`SCOPE-06`）。
- DesktopObservation / Semantic Snapshot 事件（M2，DEC-005 待建；仅保留事件帧扩展点）。
- Windows 传输（M4）、发布打包、安装器与前端工具链定案（M5，DEC-006 决策 6）。
- 任何脱离 IPC 契约的前端-runtime 耦合（`RULE-01`：`apps/ui -> runtime` 仅经 IPC）。

## 设计与决策依据

- [DEC-006](../decisions/DEC-006-ui-web-frontend-packaging.md)：UI 技术路线与唯一耦合面。
- [DEC-007](../decisions/DEC-007-local-ipc-and-runtime-service.md)：传输、帧格式、协议 v1
  请求面与单连接单未决请求纪律。
- [DEC-012](../decisions/DEC-012-ipc-event-subscription-and-wire-schema.md)（Proposed）：
  事件订阅契约与 wire schema 事实源。**契约类工作项（`M1.5-01`、`M1.5-02`）以其评审
  接受（状态转 Accepted）为前置**；`M1.5-04` 的 mock 前端不依赖该接受，可先行。
- 总计划：`EXEC-01`/`EXEC-02`（Executor owner 与事件分发映射）、`RULE-01`（依赖方向）、
  `RULE-07`（背压显式化）。
- pinned 依据：`third_party/mira/third_party/executor`（`Topic` / `LatestMailbox` /
  `MpscChannel` 公开头与 communication capability card）。

## 工作项

- [ ] `M1.5-01` 提供协议 v1 wire schema 事实源与双端一致性门禁：新建
  `docs/design/mirage-ipc-protocol-v1.md`（帧格式、请求/响应信封、消息表、错误码，
  与 `runtime/ipc` 现状互审一致），提取共享 golden vectors
  （`tests/runtime/data/ipc_protocol_golden.json`），新增 `ui/contracts` TypeScript
  镜像（消息类型 + 编解码 + 按 golden vectors 的一致性测试）。验收：schema 文档评审
  通过；C++ 与 TS 测试消费同一 vectors 全绿。
- [ ] `M1.5-02` 提供 service 事件订阅能力并冻结事件帧语义：按 DEC-012 决策 2-5 实现
  `events.subscribe` / `events.unsubscribe`、`event` 信封（`v`/`seq`/`event`）、
  `task.updated` / `host.status` / `events.overflow` 事件集、hello `events` 能力通告、
  `executor::comm::Topic` + 每连接有界队列（drop-oldest）+ 响应优先写出、断连清理。
  验收：DEC-012 验证方式列出的协议/服务测试全部通过，M1 既有协议测试零回归。
- [ ] `M1.5-03` 提供开发期 dev bridge 工具：`apps/devbridge` 将 Unix domain socket 上的
  协议帧透传为 WebSocket 帧（双向、保序、有界缓冲、显式关闭），进程内 Executor 纪律
  完整适用。验收：浏览器经 WebSocket 对真实 `mirage-service` 完成 hello 与
  task submit/inspect round-trip；工具可被 SIGINT 干净关闭。
- [x] `M1.5-04` 提供前端工程骨架与 mock 全流程可视化：`ui/` 初始化 Web 工程（开发期
  暂定 Vite + TypeScript，组件框架在实现评审时定选，均为暂定默认值、不构成 DEC-006
  决策 6 的定案）；基于 `ui/contracts` 实现 mock transport（内存任务状态机 + 事件
  模拟）；交付 Workspace（服务/主机状态、任务提交）与 Tasks/Execution（任务列表、
  step 级进度、结果与错误视图）。验收：浏览器中以 mock 数据完成 submit → step 级
  实时进度 → cancel → 终态的全流程可视化，无任何后端依赖。
- [ ] `M1.5-05` 提供前端对真实 Service 的联调与降级路径：经 dev bridge 连接真实
  `mirage-service`，事件订阅实时刷新；订阅不可用（`unsupported` / hello 无
  `events` 能力）时自动降级为 `task.inspect` 轮询；事件 `seq` 跳跃或 overflow 触发
  resync。验收：真实 submit → 实时进度 → cancel → 终态闭环在 UI 可见；降级路径在
  人为关闭订阅时行为正确。
- [ ] `M1.5-06` 将前端门禁接入 CI：TS 一致性测试、前端构建与 lint 以独立 job 进入
  GitHub Actions，不破坏既有 CMake 预设矩阵；golden vectors 保持单一事实源（C++ 与
  TS 测试读取同一文件）。验收：CI 全绿且包含前端 job。

工作项依赖关系：`M1.5-04` 可立即开始（仅依赖 DEC-012 中的消息表草案作 mock 依据）；
`M1.5-01` → `M1.5-02` → `M1.5-05`；`M1.5-03` 依赖 `M1.5-02` 的帧语义定稿（实现可在
其评审期间并行）；`M1.5-06` 随 `M1.5-01` 起逐步接入。

## 风险与阻塞

- **DEC-012 处于 Proposed**：事件契约细节（事件集、溢出策略、能力通告）待维护者评审；
  评审修改会波及 `M1.5-01`/`M1.5-02` 的验收标准。解除条件：DEC-012 转 Accepted。
- **契约漂移**：schema 文档 / C++ / TS 三处一致性靠 golden vectors 测试锁定；在门禁
  接入 CI 前（`M1.5-06`），本地运行双端测试是提交前纪律。
- **前端工具链未冻结**：Vite/包管理器/框架均为开发期暂定，若 M5 定案改选，迁移范围
  限于 `ui/` 工程文件与 CI job，不触及契约层（`ui/contracts` 为纯 TS + JSON，无框架
  依赖）。
- **dev bridge 的工具定位**：必须保持开发期工具边界（不进安装包、不产生产品承诺）；
  若未来产品化壳内 IPC 桥需要 WebSocket 形态，属 M3 壳 PoC 范畴重新评估，不复用
  dev bridge 的定位。
