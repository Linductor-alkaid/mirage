# 原生 Agent 对话页

当前入口为 `mirage-native`（M6-01/02/03，DEC-033/034），一个 EUI-NEO GLFW/OpenGL
窗口进程。UI 主线程持有逐会话消息有界的 `ChatModel`，视图以 EUI DSL 合成，私有窗口适配负责
系统窗口动作。RuntimeBridge 通过 Executor blocking worker 连接独立 Runtime Service，MpscChannel 将有界事件交回 UI；模型请求在服务内执行。

界面不限制会话个数、每会话显示最近40轮（80条消息），每条草稿最多16 KiB。
会话、轮次和回复以IPC快照/事件为事实源；草稿、主题、侧栏宽度保留在UI进程内。
提交后显示运行中，终态回复或明确错误；停止按钮调用session.chat.cancel。
服务重启恢复的旧会话保留产品ID，首次harness提交延迟打开当前Mira会话并建立有界映射；
历史、编辑重发与续聊仍使用稳定产品ID（DEC-039），不恢复旧Task或桌面task.submit对象。

## Direction contract

THESIS：桌面 Agent 的对话工作台；先读清当前会话，再在底部描述任务。

OWN-WORLD：参考 ZCode 的 Zai Light/Dark 中性灰、窄侧栏、细分隔线、紧凑工具条，
深色实心发送按钮；随应用交付的 Noto Sans SC 中文无衬线字体，图标使用 Font Awesome。

STORY：用户在设置配置模型服务，返回会话提交文字任务，读取Mira回复或明确失败；
必要时停止轮次。Linux Xorg 已接桌面观察与输入工具；workflow 执行产品面另行推进。

FIRST VIEWPORT：1180×800 无边框窗口，260px可调侧栏与60px原生标题条保留；
空会话为居中问候与672px输入框。有消息后，右对齐轻灰用户气泡、无边框Markdown回复，
主区宽≥864px时阅读列扣除96px留白，否则扣除48px，最大800px；底部16px圆角输入随文字增高。
附件/访问权限/上下文占比/模型/思考深度/发送构成紧凑工具条；最小860×620保持操作可达。

FORM：用户指定 ZCode 参考，code-led 原生桌面对话页；seed key：user-zcode-native。

FINISH：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 模型配置与提交意图（M6-07 / DEC-037）

以 ZCode `ModelProviderSectionLayout` 的服务商导航和右侧详情为布局依据；
宽 ≥700px 时内部导航176px；小于700px时使用全宽命名服务商选择器，保留可滚动表单。

切换只在service ACK后更新composer，活动任务/存盘失败拒绝切换；API Key仍经环境SecretRef。

每轮 IPC 携带 access 和 reasoning。按
[DEC-054](../decisions/DEC-054-scoped-complete-desktop-actions.md)，read_only 保留窗口/
应用/语义观察；default 另有 wait、窗口激活、语义引用点击与完整 key/text。
缺 Provider 或完整释放/scope 能力不注册；动作经共享 PermissionController 逐次判定，
共享租约避免会话与工作流交错输入。每次修改必须携带最新观察 scope/epoch 和目标窗口，
派发成功仍显示 verified=false。工具过程沿用已有 Part 事件，输入文字仅投影目标、
字节数和 scope/epoch；释放失败回执为 uncertain 并保持 fence，不自动重试。
模型声明supports_reasoning后才提供Mira公开minimal/low/medium/high，默认省略。
文本附件由前端Executor有限任务读取；只接受普通文件，8KiB/4个上限，UTF-8校验，
拒绝FIFO/符号链接（Linux），借generation与单调附件ID保护清空/发送ACK竞态。
附件以明确不可信用户上下文送入现有TextPart，未开放Mira file/image能力。

## DEC-041：当前会话密度、进度与输入法（2026-10-05）

本节覆盖之前各轮的视觉数值：正文/输入14EM、行距22px，Markdown标题18/16/15EM，
品牌18EM/28px图、欢迎26EM、顶部标题14EM、历史行40px、新建/返回按钮36px，设置标题24EM。
输入最小50px、上限168px，沿用Noto Sans SC的统一EM测量。附件/权限留左侧；上下文、
实际字宽模型按钮、思考、发送为右侧组，最小860px和长名称均无重叠。

等待行显示轻量三点动效与单调时钟用时；真实预览到达后渲染Markdown，完成后显示本次
观察到的耗时，恢复历史缺少计时不估算。既有Executor仅在活动时注册100ms周期刷新，
停止时取消并在外部owner关闭。IPC预览完整快照限16KiB，订阅显式chat_preview=true；

### 2026-10-17：过程信息说明（DEC-098）

## 失败正文与原因分离（M6-46，DEC-104）

轮次失败/取消保留当前已收到的模型正文，失败原因单列在正文下方，不写入正文，

和历史恢复；UI 识别 terminal.reply 为正文，避免过程区与正文重复。纯错误轮次不
伪造模型答复。迟到预览不能修改终态；无规范答案的中断预览仅当前 UI 保留，不冒充
持久化规范历史。正文/错误变化都使测量缓存失效。失败状态与工具证据仍保留，
不能因保留模型文本而改变动作核验或任务成功判定。

### 2026-10-23 长会话几何预算（M6-48）

### 2026-10-23 Markdown 视口与选区（M6-50）

正文和过程 text 段消费 EUI 公共 `.viewport(top,height,64)`，局部 top 从消息/过程
行几何及当前 scroll offset 推导。全高仍使用公开 estimateHeight，不改变原有
跟随、手动浏览或过程展开规则。EUI 在 UI 线程用有界布局计划复用解析文档/inline
几何，构建与可见区域相交的块、表格行与段落行；依赖中无新线程或调度设施。

视口树不包含完整选区信息，因此 Markdown 按下时临时调用默认完整 builder，
同字体/style/宽度及全局未滚动坐标布局，沿用原 CJK 适配与 selection adapter。
只保留选区需要的复制数据，临时树立即释放；拖选和引用保持原 UTF-8/Markdown
渲染语义。此首次选择仍可能有长文布局成本，不宣称所有交互均达到帧预算。
依据 EUI-20261023-001、[PR #117](https://github.com/sudoevolve/EUI-NEO/pull/117)
及[验证记录](../benchmarks/native-long-session-20261023.md)。


### 2026-10-23 长历史溢出探测（M6-51）

在当前会话 prepare 后，未变化行的精确完整宽度高度与全部行间距可证明
是否必然需要滚动条。只有超过视口加 1 个逻辑单位时，测量 UI 的首轮回调
省去变化长文布局；实际 gutter 宽度的高度、行位置和 scrollMaxOffset 始终
精确计算。宽度/字体/源失效导致已知高度不足时保留完整测量；大量消息仅凭行间距也
可能足以证明溢出。真实树不走代理路径。
这依赖 pinned ScrollView 首轮只判断溢出的消费行为，升级时须回归；不改变
滚动条出现、正文宽度或消息内容。依据 DEC-108，详见
[性能记录](../benchmarks/native-overflow-probe-20261023.md)。


### 2026-10-23 稳定过程段隔离（M6-52）

不同消息本来独立；同一回复的已完成过程段和当前预览也按既有 Part ID 分开保留
几何。正文更新不再重测未变的过程段，过程/时序更新不再重测未变正文；段落增删、
重排、内容修订和展开按实际依赖失效。每次更新重新合计位置和总高，旧合计不用于
溢出证明。80 消息、两宽度和 8 MiB 快照预算沿用，字体/缩放/会话/预算回退不变。

完全离屏 text 过程段不进入 Markdown 构建，保留高度；进入视口（含 64 逻辑单位
预留）时恢复。单一活动 Markdown 源仍遵循 EUI 完整解析，不能以空行冻结前文。
依据 DEC-108，方法和限制见[验证记录](../benchmarks/native-settled-segments-20261023.md)。
