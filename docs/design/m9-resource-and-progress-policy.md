## 现状与迁移边界

以下来自本轮消费的 Mira `560da5ec` 和 Mirage 当前工作树，不是已实施的新默认。

| 当前约束/存量 | 所属位置 | 迁移要求 |
| --- | --- | --- |
| 模型 16 步、工具 32 次、最终轮关闭 | ModelLayer harness | M9-02 公开能力到位后移除累计停止，保留局部恢复/期限 |
| profile 固定 22 倍输出包络 | ModelLayer profile | 改逐请求真实准入及累计实际用量，不能传最大整数 |
| 动作 records 32 条 | DesktopActionVerification | 有界活跃/未确认记录与归档分开，不能遗忘副作用 |
| native capture 交互 32/只读 8 次 | DesktopImageTurn | 改受管流、固定帧槽及单次工作预算，保留授权状态 |
| X11 capture 4 次 | DesktopImageTurn | 与上项一并审计，不能换路径后撞上隐藏上限 |
| 视觉后观察 64 次 | DesktopActionVerification | 局部核验工作/期限与长期任务生命周期分开 |
| 原始 capture 32 MiB、预览 8 MiB、图像年龄 5s | DesktopImageTurn | 容量/新鲜度保留，ROI 与标定引用不能暗中续期 |
| usage anchors 512 个会话 | ObservedProvider | 保持有界，压缩后校准；淘汰有明确 fallback |
| MemoryEventStore / loop 私有 history | ModelLayer / pinned ConversationLoop | 上游持续循环同时核对保留策略；不得无界积累或绕行私有历史 |
| 新对象表 256 对象/512 KiB 逻辑存量 | VisualScene | 已冻结首增量，具体字段/暂存上限见对象状态设计；没有像素/队列 |

资源达到容量时报告背压/拒绝；主任务是否等待、降级或报错由实际原因决定，不能
把活动容量、视觉次数与用户任务总次数混为一谈。连续帧/GPU 的全链路预算仍需
M9-07 在实现前冻结，并用目标设备实测 RSS/拷贝及延迟。

## 无进展判定表（实现前冻结）

| 情况 | 观察与处理 |
| --- | --- |
| 工具很多，但目标/事实/待办有推进 | 保留累计统计，继续；不按次数终止 |
| 同工具同参数、同失败类别、相关观察未变 | 去重提示与分类恢复；阈值待针对基线冻结，不无限重试 |
| 声明条件尚未满足、授权和本地观察仍有效 | 本地有期限等待；超时返回局部结果供 Mira 决策 |
| 未派发且引用过期/局部变化 | 当前身份可确认时有限重定位，否则返回歧义/新观察 |
| 输入已派发但后条件未证实 | 仅只读重验；保留不确定副作用屏障，不重发输入 |
| 身份丢失/目标替换/标定依赖变化 | 挂起受影响语义；按需重识别/重标定，不误继承 |
| 用户取消、接管或权限撤回 | 停止相应自主动作/等待，释放输入，拒绝迟到结果 |

## A/B 记录与预先门槛

需同模型/模式、同页面起点、同任务与权限状态作配对；每个样本记录版本、源/帧
条件、任务结果和失败码。主指标为完成率、动作零/一次派发、错误继承数；次指标
为模型往返、图片/像素/input tokens、实际 OCR/detector 调用、P50/P95 以及本地
资源。关键正确性负例要求错误派发/跨源继承为零；资源必须不越已冻结上限。

存量，不代表连续帧采集 CPU/GPU/RSS 或端到端收益。
