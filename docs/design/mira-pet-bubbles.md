## 1. 用途与呈现原则

用户在其他应用工作时，通过头顶气泡感知 Mira 正在思考或正在表达什么。维护者确认：
**思考气泡用于体现正在进行的状态，不以让用户读完思考过程为目标，采用连续横向滚动。**
对话气泡只用一句很短的话概括当前输出的核心大意，无需表达完整信息。

角色仍使用既有九态动画；不恢复底部状态条，不增加阅读历史、展开、复制或输入入口。
正文、完整思考、权限确认及结果详情留在主窗口。气泡内容是临时呈现，不作为执行指令、
历史、Token 用量或成功事实。

[动画设计预览](previews/mira-pet-bubbles.html) 使用现有角色资源和明确标注的示例文字，
可直接打开；它是浏览器设计演示，不是原生产品运行或平台窗口验收。

## 2. 两种气泡

| 项目 | 思考气泡 | 对话气泡 |
| --- | --- | --- |
| 形状 | 横向圆润长泡，下接两个逐渐缩小的圆泡，指向头部 | 圆角短句框，下接短圆润尾尖，指向头部 |
| 内容 | 一行实时思考预览；能力缺席时滚动“正在思考…” | 一句核心概括，如“已找到原因，正在修复。” |
| 运动 | 从右向左匀速连续滚动，不分页、不逐字闪现 | 静止；仅在概括有实质变化时替换 |
| 尺寸 | 外宽等于角色画布宽 W；正文只占一行 | 外宽也为 W；正文只占一行，不变成聊天面板 |
| 空内容 | 使用明确状态提示，不拿历史思考填充 | 暂用“正在回复…”，收到可靠概括后替换 |

默认 W=240 逻辑像素，含左右各 12px 留白，正文视口 216px；字体沿用原生 Noto Sans SC，
13px/20px。泡身高 36px（正文 20px，上下各 8px），尾部预留 14px。思考圆角 18px，
对话圆角 12px。气泡中心与角色画布中心对齐，尾端离**固定头部安全锚点** 8px，
不跟随每帧头部微动而抖动。锚点由当前素材 alpha 边界核对后冻结，不能把画布顶部当头顶。
当前原生窗口逻辑尺寸固定 264×322，角色画布 240×240；合成倍率测试按同一比例放大文字和几何。角色尺寸设置尚未交付，不声明任意缩小场景可读。

沿用原生明暗主题：浅色泡身 `#ffffff`、正文 `#202020`；深色泡身 `#222222`、正文
`#eeeeee`。思考圆泡和对话尾尖同泡身色。用一个轻柔向下阴影区分桌面背景，不叠加
描边、光晕、毛玻璃或彩色状态灯。示例预览中的桌面底色仅用于看清边界。
文字对比度需达到 4.5:1；在亮/暗/复杂桌面背景下分别验证。

## 3. 思考行如何滚动

1. 模型活动开始立即显示思考气泡；文字流尚未到达或 Provider 不提供可展示思考时，
   滚动“正在思考…”，其来源明确为状态提示。只有当前请求的可展示思考流才能替换它。
   `redacted` 内容、签名、工具参数和供应商未公开内容不进入气泡。
2. 文本按 UTF-8 字符边界校验，换行/连续空白归一为单个空格，不渲染 Markdown、代码
   块或链接。保持一行，不按句停留。新片段接入行尾，不因每个 token 更新重置滚动位置。
3. 速度 24 逻辑像素/秒，前后副本间留 32px；短文字也循环，避免变成静态状态条。
   初次出现从视口左端开始，随后向左移动，重复副本从右侧接入，无跳回、无两端渐变遮字。
   位移由单调时钟计算；UI 卡顿直接推进到当前相位，不排队补帧。
4. 只保留当前请求最近至多 2KiB 思考文本；超预算沿完整字符边界丢弃最早文本，保留
   最新内容并标记截断。实时显示不承诺每个字都出现。容量收缩时按删掉文本的实际测量
   宽度调整偏移，保持可见位置；新请求/重试则清空文本并重置相位。
5. 尊重减少动态效果：替换为最新一行静态预览，超宽省略，保留“思考中”可访问状态；
   此偏好是主动选择的替代呈现，默认仍连续滚动。屏幕阅读器只播报阶段变化，不逐字播报。

上述值已用于原生 Linux 实现和 1×/2× 合成渲染测试；物理 DPI/多屏验证仍开放。
“实时”指随可用流更新，不宣称硬实时性或端到端延迟保证。

## 4. 输出如何概括

对话气泡呈现**当前已收到文本的核心大意**，以对象/动作/结论为中心，通常 8～18 个
汉字或相当视觉宽度，最多 24 个 Unicode 字符且必须适配一行实际测量宽度。中文、英文和
混排均按字体实测，不能把字数当像素宽度。

| 当前模型输出（示例） | 气泡短句（示例） |
| --- | --- |
| 找到了配置中的路径错误，接下来会修改配置并重新检查。 | 找到路径错误，正在修复。 |
| 已修复配置，验证已经通过，下面是具体改动和检查记录…… | 配置已修复，验证通过。 |
| 还无法确定是哪项配置导致失败，需要补充日志后继续排查。 | 原因未明，需要补充日志。 |
| 当前操作需要你确认权限，确认后我才能继续。 | 需要确认权限后继续。 |

这里的短句只是模型表达的概括，不使权限或任务终态发生改变。不得把“尝试修复”压缩成
“已修复”，或把“不确定/未验证/需要确认”删掉。先保留这些限定语，再压缩对象和细节。

生成路径由 Runtime/Integration 对既有正文预览及规范结果做有界投影，桌宠只消费
短句。当前使用抽取式压缩：去除礼貌开场、标题、列表/代码外壳，选择当前输出中的
主要动作或结论句，去掉重复和非必要从句；不单独调用摘要模型、不要求正文每次额外输出
固定格式。**截取前 N 字不是概括算法**；若候选不能保留核心含义和限定语，暂留
“正在回复…”或最后仍有效的本请求概括，不显示断裂句，不借用其他请求的内容。

流式正文只从已经闭合的句子/行选择概括，不把当前token尾部（如“配置已修”）当成
完整结论；无可靠短句时显示“正在回复…”，有旧的完整短句则保持到新句闭合。英文
句号/问号/感叹号、列表、大小写和逗号从句与中文同样处理。逗号分句不得丢掉原句的
否定、不确定或未来限定；泛泛的早期不确定开场不会压住后来已闭合的核心事实。
规范终态允许没有标点的完整短句，包括42、OK和带负号数值。摘要扫描前16KiB预算，
预算切点不作为闭合句，不截断后半截来虚构短结论。

示例/引用/假设按段落范围处理，不能只丢掉“示例：”标题后把下一行“配置已修复”
当成当前执行事实。Markdown示例节直到同级/更高非示例标题才结束，嵌套引用或子节
不缩短外层范围；普通示例/条件段在其正文之后的空段结束。明确的引用和条件内容不
作为事实短句候选；没有可靠候选时保留提示或先前仍有效的短句。

后置限定与核心动作句按同等优先级选择较新的完整句：前面“配置已修复”不能压住
后面的“尚未测试/还无法确定结果”。反过来，旧的不确定开场也不压住后来已闭合的
核心事实；普通“No problem/No worries”礼貌收尾不提升为限定句。

正文开始时先切到对话气泡；每 500ms 至多应用一次概括变化，优先完整有意义的
句/短语，不逐 token 改写；请求级清空与安全清除不受节流限制。收到规范终态答案后重新
选择最终核心短句，正常完成保持 5 秒后消失；完成不是重新播放历史回复。无可用正文时
不虚构结论。若抽取式压缩在验收语料中无法满足上述语义要求，M8-11 保持未完成，另行
记录 Runtime 内摘要能力方案与预算，不在桌宠里旁路模型。

## 5. 气泡状态与动画独立

气泡跟随 Runtime 选定的**当前活动来源和模型请求**，不从角色动画名推断文本阶段。
既有动画首轮可以延迟切换，气泡不能等 looking 的 8.9 秒首轮结束才呈现新文本。

| 事件 | 气泡行为 |
| --- | --- |
| 当前请求仅有模型活动，无正文 | 思考气泡；有公开思考流时滚动内容，否则滚动状态提示 |
| 收到本请求首个正文预览 | 立即切到对话气泡，不再同时展示思考泡 |
| 同请求随后又有思考片段 | 维持对话泡，避免两种气泡来回闪烁；新请求重新选择 |
| 模型请求转入工具执行 | 清除该请求气泡，不拿上次回答概括解释鼠标/键盘动作 |
| 正常回答结算 | 最终概括保持 5 秒，与成功动画分别推进 |
| 新任务/请求/重试、显示归属或 owner 改变 | 清除旧内容与保持期限，只接受新身份内容 |
| 失败、取消、接管、暂停、等待确认、断连、退出 | 立即清除模型气泡；真实原因仍由主窗口表达 |
| 避让隐藏/最小化 | 同时隐藏角色和气泡，停止滚动唤醒；恢复读取最新完整快照，过期内容不重播 |

owner/source/request 身份必须完整匹配；同一身份的序号单调增加。迟到流、旧终态、
恢复的历史 ThinkingPart 和别的会话都不能重新点亮气泡。

## 6. 承载与依赖核对

现有正文 sink 与新增独立 `ModelThinkingPreviewSink` 分别传递至多 16KiB 的完整快照。
授权消费 [Mira PR#94](https://github.com/Linductor-alkaid/mira/pull/94) merge `22d9577`，
解决 [MIRA-20261014-004](../dependency_feedback/mira.md#mira-20261014-004)。PR 已于2026-10-14获维护者授权合并。
2026-10-14同步master后pin为`9e7b729`（已包含PR#94，叠加PR#95输入复用能力），
保留两项依赖升级的说明；详见本机交付记录的合并前同步证据。
不在 Mirage 解析 SSE，不把终态 ThinkingPart 当成实时流。

`hello.pet_bubbles=true` 可探测能力；`pet.status` / `pet.updated` 可选 `bubble` 承载
kind、content_origin、request_id、sequence、text、truncated、final、remaining_ms。
owner/source 从外层完整状态继承。无气泡时不写该字段，不写 kind=none；旧 wire 向量保持原字节。
完整编码不超过 4KiB；转义扩张时沿 UTF-8 边界缩减思考行并标 truncated，字段与 golden
见 [IPC 设计](mirage-ipc-protocol-v1.md#pet-bubbles)。
2KiB 尾部截断及转义预算缩减之后仍须保持行规范化幂等：截断边界留下的前导分隔空格
必须移除，使本地投影始终通过 `valid_bubble` 与 wire 解码校验，避免合法长思考流令
桌宠连接按协议错误关闭（BUG-20261017-001）。

每个活动 dialog turn 持有一对有界 LatestMailbox，规范结算释放原始预览；模型回调仅
校验/投递和投递刷新标记，Runtime 既有 25ms Executor timer 在串行投影域生成短句。
没有新压缩 worker/队列，压缩工作本身为有界单步。Topic 向订阅者广播完整状态，桌宠
LatestMailbox 只消费较新快照。滚动以单调时钟计算，复用 33ms Executor 动画 timer；
隐藏时停止渲染唤醒。终态期限使用一次延时任务，至多保留三组 TimerSubmission 句柄/future，
取消结果消费、拒绝与异常有诊断，shutdown 排空。静止泡本身不要求持续唤醒，但角色动画
仍按其既有需求更新，不宣称硬实时性。

## 7. 布局、穿透与 M8-06 门禁

240×240 的既有角色画布及 alpha 不能为了加气泡而缩小。气泡是同一受管桌宠表面的
额外上方区域；默认扩展约 58px（36px 泡身 + 14px 尾部 + 8px 间距），实际布局按
头部锚点核对。角色在桌面的原位置保持固定；显示/清除气泡不得推动角色上下跳动。
保存的位置定义为角色画布锚点，不能因窗口外框扩大改变重启位置。

气泡不抢焦、不接收点击、不作为拖动手柄；角色实体沿用拖动。X11 ShapeInput 只含
角色 alpha 输入区，不能把合成后的气泡不透明像素一并纳入实体区。视觉占位包含角色、
泡身、尾部及阴影，与输入区分别计算。平台类型和屏幕映射继续封装在 Platform 边界。

头顶空间不足时先整组约束到可用工作区；无法容纳才改在角色下方显示并反转尾部，
不得裁掉正文或扩大到其他应用的可用区之外。优先头顶、下方降级的几何变化需要确认。
多屏/负坐标/DPI、显示器移除和大小设置按当前屏幕预算处理；没有可用空间时隐藏气泡
并提供既有诊断，不能悄悄缩成不可读小字。

M8-06 必须核验**角色 + 气泡的全部视觉占位**，既覆盖键鼠目标，也覆盖截图/OCR。
气泡输入穿透并不消除真实遮挡或截图污染。避让/隐藏须同步作用于整个呈现，得到新几何
确认后重新观察；在隐藏期间到达的文字不得自行打开气泡。布局变化使占位版本更新，旧
确认不可沿用。无安全区域、几何确认失败或平台不支持时明确拒绝冲突动作。

## 8. 实施验收

| 门禁 | 通过条件 |
| --- | --- |
| 一行滚动 | 短/长中文、英文混排、空流、换行、持续追加、2KiB 截断、卡顿均不换行、不因 token 重启；速度稳定 |
| 输出概括 | 长说明、多结论、代码/列表、否定、不确定与未验证语料逐例保留核心含义；实际一行适配，非截断冒充摘要 |
| 当前来源 | 多会话选择、请求/重试清空、乱序、终态迟到、断连与新 owner 不串字、不复活 |
| 时序 | 思考到正文及时切泡，不等待动画首轮；工具执行清除；规范答案覆盖预览，保持期限正确 |
| 窗口 | 明暗/复杂桌面、工作区边缘、拖动、DPI/跨屏，角色不缩小/跳位，气泡穿透且非激活 |
| 避让 | 只覆盖气泡的目标、OCR 区域也触发避让；隐藏时新流不显现；新几何版本重观察 |
| Executor | 正常完成、异常、提交拒绝、运行中取消、超时、shutdown，future/句柄闭合且诊断可见 |
| 可访问性 | 减少动态效果可静态替代；对比度达到 4.5:1，阶段可访问名称不逐 token 播报 |

真实思考流与状态提示分别验收，提示演示不能关闭依赖缺口。Linux 原生窗口、真实会话、
ASAN/UBSAN、跨上下文/关闭 TSAN 及故障注入由 M8-11/07 取证；其他平台按 M8-10
独立验证。当前已完成 Runtime→IPC fixture、Linux 原生渲染和自动状态/安全清除回归。
详见 [实施证据](../compatibility/mira-pet-bubbles-runtime-20261014.md)。供应商在线流、
物理 DPI/多屏、桌面 compositor alpha、整组目标/OCR 避让及其他平台未执行，
负责人为 Mirage 维护者；补跑条件分别为在线模型配置、对应目标桌面和 M8-06/10 实施。
这些开放门禁不因 fixture 通过而勾选。
