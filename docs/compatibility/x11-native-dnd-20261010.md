## 范围与实现

沿用 Linux x86_64 / GCC 13.3 / GTK 3.24.41 / Python GI / 私有 Xvfb 800×600，
工作树 feat/m7-conversation-desktop-tools，HEAD c786df7。本轮未提交/推送，
未修改 pinned 依赖或锁文件，未操作用户桌面、请求模型或下载权重。系统已有
libXRes 动态库，开发包只解包到临时 SDK；来源、摘要、许可与构建条件见
[系统库核对](../supply-chain/xres-platform-library-20261010.md)。

X11 Backend 在按下前通过 XRes 取得目标连接资源范围，保存已可见根窗口；
只在本动作持左键期间跳过一个新出现的同连接 InputOutput override-redirect
辅助图层。下方首个命中仍须到达原目标，重父窗口内也不能跳过外来子窗口。
不以 PID/标题判断归属；无需复制依赖代码或增加线程/定时器。有限动作继续
由既有 Executor 调用任务、future 和动作 lease 管理。原 16 段/8 ms、1000 ms、
五秒引用、逐像素前置重验、零延迟清理和不确定输入禁止重发契约不变。

目标连接查询最多 256 条、根子窗口最多 128 个；下方分支另有 128 后代/32 层
预算。未明确归属、查询失败或超限回退严格拒绝，最终检查自己的左键释放。
按住时运动前后均核对归属，查询后再次检查截止，避免查询已经耗完预算还发送
下一步。没有扩大工具权限或公共 Provider 类型，没有新增 dependency feedback：
本问题属于 Mirage X11 映射职责。

## 方法与场景

延续第二增量真实 Screen/ROI、Mirador fusion/SoM、视觉引用、Mira 工具 registry、
权限/lease/像素守卫和 DesktopActionVerification 组合。候选由原生控件分配的
fixture 给出，不声明 OCR 真实定位或在线模型选择。原生 GtkTreeView 默认
重排行为改动 ListStore，独立读顺序；标题通过 row-inserted/row-deleted 与
rows-reordered 信号投影实际状态，避免部分原生重排不触发 rows-reordered。

| GTK 场景（11 个） | 结果 / 验证 |
| --- | --- |
| 双轴滚动、边界不变 | 原双轴效果正例与不产生效果负例保留 |
| 分隔条、禁用、首个按下后取消 | 原位移正例与失败收敛保留 |
| 原生列表重排 | Alpha,Bravo,Charlie,Delta,Echo → Bravo,Charlie,Alpha,Delta,Echo；drag-begin/drop/end 各 1，failed=0，新后条件 verified=true |
| 禁止列表重排 | 顺序不变，派发可完整完成，readonly verify/settle=false |
| 列表拖放开始后的取消 | 向下已运动至少 50 像素且 drag-begin=1；取消回执、左键释放、settle=false |
| 列表拖放中焦点丢失 | 另一连接接管焦点；focus_changed、释放、settle=false |
| 外来遮挡在图标上方 / 下方 | 两例均 target_obscured、释放、settle=false；下方遮挡不能因图标属同连接被跳过 |

每场景均检查 ActionCoordinator 已释放、旧引用重发拒绝。取消或失败后的清理
release 仍可能触发 GTK drag-drop；不把 drop 信号或安全释放解释为业务完成/回滚。
本批中断后的观察顺序保持原样，但契约不承诺应用副作用回滚。GTK 和 Xvfb 为
自有外部进程，调用与回收在有主有限 driver 内；没有私有 Mirage GUI 调度器。

机械测试另覆盖 11 类辅助窗口场景：新同连接图层正例、已可见同连接图层、
普通窗口、InputOnly、其他连接在图层上/下、两个图层、根窗口超预算、重父
窗口正例、框架内外来 sibling 与后代超预算。其他连接也在同一测试进程中，
证明同 PID 不能替代连接归属。原轮步/按住/取消/超时/异常/接管/关闭测试保留。

## 诊断与失败历史

独立诊断确认 GTK drag icon 的 ShapeInput 是完整矩形，直接绕过归属的诊断
会改变原生列表顺序；它不是产品路径验证，也不能作为安全放行理由。第二
增量的 ShapeInput 尝试仍保持撤销，本轮不用透明窗口假设。

首轮产品原生正例已经重排，但测试编译期能力标志未传出 CMake 子目录，导致
测试按“无辅助解析”预期检查、未注入中途故障；99 checks / 20 failures。
改用 target property 后组合正负通过。重父窗口首轮被拒绝：QueryPointer 在
被图标遮住的 WM frame 不返回下方 child。冻结有界层叠几何解析，补内部
遮挡与后代预算负例后通过。该改动一次被 -Werror=shadow 阻断，已改变量名；
当时命令继续执行旧二进制的结果不采信，最终验证全部在成功构建后执行。

## 复现与剩余门禁

系统有 libxres-dev 时 FindX11 自动检测；GTK 验收仍 opt-in，不自动安装。
本机临时 SDK 的附加配置为：

```bash
cmake --preset native-debug -DMIRAGE_ENABLE_GTK_POINTER_ACCEPTANCE=ON -DMIRAGE_ENABLE_X11_DRAG_HELPERS=ON -DX11_XRes_INCLUDE_PATH=/tmp/mirage-xres-sdk/root/usr/include -DX11_XRes_LIB=/lib/x86_64-linux-gnu/libXRes.so.1
cmake --build --preset native-debug -j2
ctest --test-dir build/native-debug -j2 --output-on-failure
build/native-debug/tests/gtk_pointer_effects_test /usr/bin/python3 tests/manual/gtk_pointer_fixture.py --without-xres
cmake --preset native-release -DMIRAGE_ENABLE_GTK_POINTER_ACCEPTANCE=ON -DMIRAGE_ENABLE_X11_DRAG_HELPERS=OFF
cmake --build --preset native-release -j2 --target gtk_pointer_effects_test x11_pointer_actions_test
ctest --test-dir build/native-release -R '^(gtk_pointer_effects_test|x11_pointer_actions_test)$' --output-on-failure
# 补回可选能力并重新构建；最终 Release 验证使用 ON。
cmake --preset native-release -DMIRAGE_ENABLE_X11_DRAG_HELPERS=ON
cmake --build --preset native-release -j2
```

sanitizer 使用第二增量同九项命令，配置额外提供上述 SDK 和 ON。任意图层
复用、跨连接辅助、非矩形形状命中、更多图层/复杂窗口与任意应用兼容性未验。
此规则确认同连接和下方命中，不查询实际 pointer grab 接收者；X11 查询/注入
不是原子事务，同连接内恶意隔离不在支持声明内。
