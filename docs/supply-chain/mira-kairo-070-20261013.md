## 差异与边界

上游声明（mira docs/decisions/DEC-054-kairo-0.7.0-upgrade.md，Accepted）：kairo v0.7.0 为
additive 版本，默认调度行为与 0.6.x 逐项一致，0.6.1 契约测试一字不改通过，零代码迁移。
Mira 侧命中全部"不受影响"面：无自定义 `IScheduler`、无对 `RoutingReason` 的穷举 switch、
按字段名读取 `SchedulingMetrics`。即刻采纳的能力只有默认开启的
`Executor::get_scheduling_metrics()` 计数；QoS 标注与 `AdaptiveScheduler` 注入由上游记录了
明确的触发条件后另行推进（暂缓不是拒绝），`FeedbackAggregator` 依赖 `wants_feedback()`
调度器注入，本轮无数据流。

Mirage 侧影响面：全部 kairo 使用经 `third_party/mira/third_party/kairo` 传递（Executor
owner 纪律不变，AGENTS.md 并发章节继续适用）；本仓库无直接 include kairo 新增头文件的需求。
新增公开 API（调度指标快照）为可选诊断能力，本轮不接入 Runtime 诊断出口，与上游"即刻采纳
仅计数可用"的姿态一致。License（mira AGPL-3.0、kairo MIT、mbedtls）不变；无新增依赖、媒体
或生成物。

`dependencies.lock.json` 已同步：mira commit、kairo nested pin（version 0.6.0 → 0.7.0、
commit ef821dc → 32027c2）与 notes。既有兼容性证据文档中的 ef821dc 记录为历史 pin 事实，
不回改。
